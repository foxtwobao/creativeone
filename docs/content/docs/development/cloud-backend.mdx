# 多用户云端后端

应用必须连接 Node.js 后端并登录，不再提供本地模式。浏览器只持有项目会话，不保存 TokenONE Key。新旧 UI 使用相同后端。

Reseller 使用门户根地址，应用请求统一走 `/api/apps/*`；`ENHANCER_BASE_URL` 不包含该路径前缀。New API 模型地址由 `TOKENONE_BASE_URL` 独立配置，迁移配置与验收见[本地联调](/docs/development/local-tokenone)。本机服务端环境文件已写入新模型地址与凭证，并按用户选择配置 lab IDONE 的 creativeone 应用。本机回调已登记，数据库与媒体备份后已重启生效；页面、登录跳转及分组接口通过，新管理员与旧数据归属仍待确认。

## 请求与身份

- IDONE 使用 OIDC Authorization Code、PKCE、state、nonce 和签名校验；以 `issuer + sub` 识别用户，不按邮箱合并账号。
- 管理员通过 `ADMIN_SUBJECTS` 指定 IDONE 的 `sub`，不自动提升首位登录者。
- 管理员在 `/admin/channels` 按图片、文本、视频、音频四项功能配置模型白名单、默认模型和启用状态，每项功能只保留一份配置。用户在已有模型选择器中选择允许的模型，不能直接指定分组。
- 每次调用前，服务端使用已验证身份的 `issuer`、`subject` 请求 Reseller `/api/apps/keys/ensure`，使用返回的个人 Key 和默认分组。请求不包含 `app_id`、`group_id`、`key_name` 或邮箱。未验证邮箱仍可登录，但不能调用模型。
- 用户须先在 Reseller 门户登录完成账户关联；`APP_USER_LOGIN_REQUIRED` 提供新标签页登录入口，完成后手动重试，不自动重发。分组由 Reseller 按应用统一管理，不自动授予用户权益，渠道仅限制功能与模型。
- Key 仅在请求期间留在服务端内存；数据库只保存绑定 ID。不缓存长期 Key，也不在分组无权限、停用、额度不足时私建备用 Key。
- 模型经 `TOKENONE_BASE_URL` 的 OpenAI 兼容接口访问。已实现图片生成/编辑、Responses/Chat Completions、Ark 视频任务、语音生成路由，New API 和具体渠道的兼容性需逐项验收；云端渠道不开放自定义请求脚本和 Gemini 原生协议。
- 请求错误日志仅记错误码和请求 ID，不记录 Cookie、身份令牌、Key 或原始上游响应。

保存使用 `PUT /api/admin/channels/:capability`，只接受 `models`、`default_model`、`enabled`。默认模型必须在模型列表中；空列表仅允许停用。底层保留稳定的调用 ID，每个功能由唯一索引约束；其他已有数据库若存在重复功能记录，需要先人工整理，程序不自动删配置或迁移历史任务。默认模型在列表中排首位，用于没有有效个人模型偏好时的初始选择。

## 账户、用量与历史绑定

Reseller 暂不提供账户余额和用量接口。登录并通过 CSRF 校验后，`POST /api/tokenone/account/summary`、`POST /api/tokenone/usage/query`、`POST /api/tokenone/usage/stats` 统一返回 HTTP 501 / `TOKENONE_ACCOUNT_USAGE_UNAVAILABLE`，不透传上游 404/HTML，不伪造零余额，也不回退旧 Enhance。前端没有对应展示页面或自动请求，生成流程不依赖这些接口。

部署前备份 PostgreSQL。新版为旧 Key 绑定与生成任务保留 `legacy-enhance` 命名空间，新绑定按用户、提供方和分组区分。未完成的旧视频任务拒绝跨服务查询；已保存结果保留。默认组改变继续返回 `TASK_GROUP_CHANGED`，Key 结果不明确时交管理员核验，不能删绑定重建。具体备份和回滚要求见[迁移说明](/docs/development/local-tokenone)。

## 存储与同步边界

PostgreSQL 保存账号、会话、渠道、Key 绑定、JSON 文档和生成任务；文件内容保存在独立持久化卷。所有业务读写按当前登录用户过滤，文件需要登录才能访问，不提供公开分享链接。

当前业务存储调整见[待测清单](/docs/progress/pending-test)：素材使用 `/api/assets` 单项接口，画布使用 `/api/projects`，设置按字段提交 `/api/settings`，提示词来源和插件记录使用对应条目接口。ID 和时间由服务端生成，浏览器只缓存服务端响应；图片/视频历史直接读取 `/api/history/:capability` 的服务端任务记录。插件私有键值仍保存在账号文档中，版本由服务端维护，不要求客户端提交 revision。

修改自动保存，账号栏通常只显示「正在保存」或「已保存」，失败时提供手动重试。刷新读取服务端结果；当前不是实时协作编辑，同一项目字段的并发提交按服务端处理顺序保存，浏览器不整份回写账号列表。不同字段及不同项目的修改会保留。

`/api/works` 和 `/api/prompts` 在后端搜索、筛选及分页。图片缩略图缓存在服务器文件卷；提示词内容首次使用后缓存在 PostgreSQL，后台按账号设置刷新，关闭页面不影响。素材 ZIP 使用 `/api/assets/export` 从服务器流式打包，浏览器下载单个文件。以上真实模型、插件与生产部署行为仍需按待测清单验收。

浏览器不再持久化业务副本，也不读取旧本地数据。离线无法首次启动；已打开页面的 JSON 保存失败仅保留在当前页面内存中，媒体上传失败直接报错。有未保存内容时关闭或刷新页面会触发离开提醒，退出登录前也会检查保存状态；继续离开会丢失未保存修改。

文件回收由服务端核对引用：移除素材/画布引用或明确请求删除后，仅回收没有其他文档和可见任务/历史引用的文件。隐藏历史或作品中的一处不一定释放文件；仍在处理的任务不会因此取消。当前没有任务保留期限、按年龄裁剪或自动清理未提交上传文件的策略。

本地 Codex/Claude Agent 的进程、连接凭据和会话仍属于当前设备，不纳入云同步，也不由 IDONE 管理。本地 Agent 默认不自动连接；在可信设备上手动连接，其本地历史仍由本地 Agent 管理。不要在公用浏览器保存本地 Agent 凭据。

## Docker 部署

服务器版只使用一个应用镜像 `<Docker Hub 用户名>/creativeone`，包含 Nginx 前端与 Node.js API；数据库使用独立 PostgreSQL 容器。对外只发布应用 3000 端口，4011 API 端口不映射到宿主机。应用以非 root 用户运行。

1. 按根目录 `.env.example` 创建 `.env`，设置 `APP_IMAGE`、`APP_PORT` 和独立 PostgreSQL 密码（当前连接串使用密码原文，请使用 URL-safe 随机密码）。`APP_IMAGE` 使用已发布的镜像标签，生产建议固定版本或 `sha-` 标签。
2. 在同一份根目录 `.env` 中填写 IDONE Client ID/Secret、Issuer、管理员 sub、Reseller 地址/应用接入凭证和 TokenONE Base URL。Compose 的 `environment` 已逐项列出这些参数，不再读取 `server/.env`，也不需要挂载配置文件。不要把密钥写入前端环境变量或提交 Git。仅启用登录与同步时，三个 Reseller/New API 连接参数均可留空；应用专属 Discovery 留空则使用标准发现地址。
3. `APP_ORIGIN` 必须是浏览器访问的完整 origin，无尾斜杠，例如 `https://creative.example.com`。在 IDONE 注册回调 `https://creative.example.com/api/auth/callback`，启用 `openid profile email`、PKCE S256 和 `client_secret_post`。Issuer 必须与 discovery 和 ID Token 的 `iss` 完全一致。
4. 让服务容器能够解析并通过 HTTPS 访问 Reseller、New API 和 IDONE。本地 Caddy CA 使用 `LAB_CA_CERT_FILE` 配合 `docker-compose.lab.yml` 只读挂载并设置 `NODE_EXTRA_CA_CERTS`，不能关闭 TLS 验证。配置变更后重新创建应用容器；步骤见本地联调文档。
5. `MEDIA_DOWNLOAD_HOSTS` 支持精确主机名和 `*.域名`，多个以逗号分隔，例如 `*.volces.com,*.volcengine.com`；泛域名同时匹配根域名和各级子域名，不匹配相似后缀，非默认端口需显式配置，TokenONE 主机默认允许。上游结果域名较多时，可在根目录 `.env` 设置 `MEDIA_DOWNLOAD_HOSTS=*` 并重新部署应用，允许下载上游返回的任意 HTTPS 主机地址。默认留空，仅允许 TokenONE 主机。此规则同时影响图片和视频结果下载；使用 `*` 仍禁止非 HTTPS、URL 内嵌凭据和重定向，文件大小限制保持不变。Compose 已传入该环境变量。
6. 使用已发布镜像执行 `docker compose pull`、`docker compose up -d`；源码构建使用 `docker compose -f docker-compose.yml -f docker-compose.cloud.yml up -d --build`，也可使用 `docker compose -f docker-compose.local.yml up -d --build`（需要支持 include 的 Compose）。生产环境在外层配置 HTTPS 反向代理。镜像设置 `NODE_ENV=production`，IDONE 必须使用 HTTPS，不能直接复用本机 HTTP 联调配置。
7. 管理员登录后进入「功能模型配置」，分别编辑图片、文本等功能的真实可用模型、默认模型和启用状态，刷新页面生效。

模板只列镜像、对外地址/端口、数据库密码、IDONE 身份配置和三个模型服务连接参数。会话、上传限制沿用下表已确认默认值；内部端口、媒体目录和生产模式由镜像设置，无需重复填写。个人 Key 和应用默认分组由 Reseller 管理；应用凭证必须具备 `keys:ensure`、`groups:read` 权限，不配置暂不支持的账户与用量权限。

Compose 使用项目独立的 `postgres`、`media` 两个命名卷，数据库不发布宿主机端口；不会共享 IDONE 或 TokenONE 的数据库。服务启动时建表，不迁移旧浏览器数据。备份时需要同时备份 PostgreSQL 和媒体卷，恢复时保持一致；不要使用 `down -v` 除非明确要删除所有项目数据。

数据库镜像固定大版本为 `postgres:18-alpine`，数据卷挂载到 `/var/lib/postgresql`，由官方镜像使用版本专属数据目录；媒体卷仍挂载到 `/app/data/media`。本配置适用于新部署。已有 PostgreSQL 17 或更早版本的数据必须先备份并通过导出/恢复或 `pg_upgrade` 迁移，不能直接替换镜像或仅调整挂载路径。此配置变更不升级正在运行的本机数据库，也不修改 IDONE、TokenONE 的数据库部署。

此配置按单个后端实例设计。服务重启时，未确认结果的同步模型任务标记为 `unknown`，不会自动重发。不要直接横向扩容服务实例；异步视频任务仍可按任务 ID 查询。

镜像内用 Tini 与启动脚本管理 Nginx/API：任一进程退出会停止另一进程，交给 Compose 的 `restart: unless-stopped` 重启。上传与模型等待沿用已确认边界，不额外重试收费调用。Nginx 配置已包含在镜像中，无需挂载配置文件；`/assets/` 与 `/icons/` 缺失资源返回 404，不再返回 SPA HTML。部署后仍需验收登录、媒体上传、静态资源、流式响应和卷持久化，不能据配置检查宣称生产联调完成。

## 镜像工作流

`.github/workflows/docker-image.yml` 只发布服务器版 `creativeone`，支持 `linux/amd64` 与 `linux/arm64`。沿用仓库 Secrets `DOCKERHUB_USERNAME`、`DOCKERHUB_TOKEN`，不会读取或上传本地 `.env`。Docker 构建上下文排除依赖目录、构建产物、密钥文件及数据目录。

- `main` 相关变更推送：构建并发布 `latest`、分支和 `sha-` 标签。
- `v*` 标签推送：发布版本与 `sha-` 标签，不覆盖 `latest`。
- 手动运行：发布所选分支/标签及 `sha-` 标签，只有选择 `main` 才更新 `latest`。
- Pull Request：只构建，不登录 Docker Hub、不推送镜像。

前端和后端同一镜像、同一提交，不再需要 `creativeone-server` 镜像。原文档镜像和 GitHub Pages 改为仅手动触发，不参与服务器版本的自动发布。保留原有上游项目文档作参考；当前服务器部署以本页为准。

## 从 Enhance 切换至 Reseller

请按[Reseller / New API 联调](/docs/development/local-tokenone)完成凭证、身份源、CA、备份、命名空间迁移和验收。必须使用包含本次修改的新镜像，不复用旧应用凭证或数字分组 ID。回滚时保留切换后的新增业务数据，并恢复配套旧代码、配置及数据库，不能仅切换镜像。

## 本地开发

IDONE 应用专属元数据通过 `IDONE_DISCOVERY_URL` 配置，应用名应与 IDONE 中创建的专用客户端一致，不得复用其他项目 Secret。显式 Discovery 的 Issuer 会单独严格核对。开发时默认仅回环地址允许 HTTP；同主机局域网 HTTP 需要明确设置 `IDONE_ALLOW_HTTP=true`，仅用于可信开发网络，`NODE_ENV=production` 时拒绝 HTTP。签名、Issuer、Audience、PKCE 等校验不关闭。

源码开发（不使用 Docker）才需要按 `server/.env.example` 创建 `server/.env`。启动独立 PostgreSQL，并在该文件配置可用 `DATABASE_URL`。在 `server` 目录执行 `npm ci`、`npm run dev`；在 `web` 目录执行 `npm run dev -- --port 3001`。Vite 默认将 `/api` 转发到 `127.0.0.1:4011`，可在 `web/.env.local` 使用 `VITE_API_PROXY_TARGET` 覆盖，`APP_ORIGIN` 应为 `http://localhost:3001`，浏览器也必须使用这个 origin。

`npm start` 面向容器注入环境变量，不自动读取 `.env`；本地开发使用 `npm run dev`。前端始终要求后端和登录，不再使用云端模式开关。

仅联调身份和存储时，可暂不设置 `ENHANCER_BASE_URL`、`ENHANCER_APP_CREDENTIAL`、`TOKENONE_BASE_URL`。相关管理/模型接口明确返回「未配置」，不会使用占位凭据或自动连接其他服务。

Reseller 仅使用新签发的应用接入凭证 `ENHANCER_APP_CREDENTIAL`，不复用旧 Enhance 凭证或管理员令牌；应用默认分组按 New API 分组名核验，用户需已有相应权益。

迁移前的本机联调记录（不代表新的 lab 环境已验收）：使用 `http://192.168.10.38:3002`（不替换原 3001 前端）、`http://192.168.10.38:8000` 的 IDONE 应用 `creativeone-local`、4013 后端和仅回环暴露的 5433 PostgreSQL。数据库由 `creativeone-local-postgres` 容器及同名持久化卷保存；媒体目录为 `server/data/media`。业务测试用户位于 AgentONE 组织，不具备 IDONE 系统管理员权限，随机测试密码仅保存在本机 `server/.env` 的 `LOCAL_TEST_PASSWORD`，不要提交或复制该文件至文档。

旧环境启动记录（切换 Reseller 时请使用迁移说明）：先 `docker start creativeone-local-postgres`，在 `server` 目录执行 `npm run dev`，在 `web` 目录执行 `npm run dev -- --host 192.168.10.38 --port 3002 --strictPort`。浏览器统一使用 `192.168.10.38:3002`，否则 Origin 和回调不匹配。现有 IDONE Compose 叠加 `deploy/idone-local.override.yml` 配置局域网端口及 Issuer；重新创建该容器时也应保留此覆盖配置与原数据库连接。

改变 Issuer 会改变 OIDC 身份命名空间：旧 localhost 的项目身份/数据不会按邮箱自动并入新 IP 身份。旧数据保留在数据库，如有实际业务数据需另行确认迁移；不要通过忽略 Issuer 来合并身份。当前已验证 IP 地址下的真实授权、回调、管理员识别和退出。

## 已确认运行边界

| 环节 | 默认值 | 到达边界后的处理 |
| --- | --- | --- |
| 登录会话 | 7 天 | 要求重新登录 |
| OIDC 登录流程 | 10 分钟 | 废弃流程，重新发起登录 |
| 单个媒体文件 | 100 MiB | 上传或结果持久化失败，不自动重发模型调用 |
| JSON 请求 | 20 MiB | 返回 413，未保存修改仅保留当前页面内存 |
| 模型请求 | 10 分钟 | 结果不确定时标记 unknown，不自动重试收费请求 |
| 画布自动保存 | 原有 400ms 防抖 | 修改后触发保存，退出/重试前主动提交待保存内容 |

## 验证状态

隔离 PostgreSQL 上的接口测试覆盖未登录、管理员/CSRF、用户及文件隔离、功能模型白名单、分组权限失败、SSE 文本留存、版本冲突、删除标记、文件不可覆盖和账号切换。运行测试需显式传入独立、名称以 `_test` 结尾的 `TEST_DATABASE_URL`，在 `server` 目录执行 `npm test`，不得使用生产库。

前端登录后页面用模拟 API 做了浏览器冒烟验证；随后使用本机真实 IDONE 验证授权码/PKCE、应用级 JWKS 验签、回调、业务管理员识别、数据库读写和本地退出。未执行构建或类型检查。真实浏览器登录体验、生产 IDONE、Reseller Key 获取、实际图片/视频/音频生成、双设备同步和 Docker 持久化重启仍需按待测清单联调，不能据此宣称已完成生产验收。
