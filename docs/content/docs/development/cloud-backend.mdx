# 多用户云端后端

应用必须连接 Node.js 后端并登录，不再提供本地模式。浏览器只持有项目会话，不保存 TokenONE Key。新旧 UI 使用相同后端。

Reseller 使用门户根地址，应用请求统一走 `/api/apps/*`；`ENHANCER_BASE_URL` 不包含该路径前缀。New API 模型地址由 `TOKENONE_BASE_URL` 独立配置，迁移配置与验收见[本地联调](/docs/development/local-tokenone)。本机服务端环境文件已写入新模型地址与凭证，并按用户选择配置 lab IDONE 的 creativeone 应用。本机回调已登记，数据库与媒体备份后已重启生效；页面、登录跳转及分组接口通过，新管理员与旧数据归属仍待确认。

## 请求与身份

AppONE 新协议已部署 lab 并通过双域名 HTTPS 协议检查，完整账号登录和真实 SSO 仍待联调，见[待测清单](/docs/progress/pending-test)。登录/注册复用 `ENHANCER_BASE_URL`，通过 `/api/auth/login` 顶层导航到 Reseller `/auth/enter`，只传产品 `RESELLER_APP_ID`、当前可信 `sourceOrigin` 和可选注册标记。平台认证完成后直接访问 `/api/auth/oidc/start`，由本应用使用固定业务客户端独立完成 OIDC；`/api/auth/callback` 仅处理本应用授权响应。登录流程不配置 HomeONE、Site 或渠道映射，不接收 appState；可选页面导航单独配置可信 HomeONE 静态资源与公开 policy。

原页面仅在服务端保存浏览器绑定的导航记录，保留 600 秒；缺失、过期或被同 origin 其他标签替换时返回 `/studio`。业务 OIDC 事务固定 300 秒，绑定客户端、issuer、精确 redirect_uri、origin、浏览器 Cookie 和返回页面，并一次性消费。失败与过期显示手动重试；本地退出清除会话和当前浏览器未完成事务，不自动重新登录。用户、业务数据及管理员授权沿用原始 issuer/sub，不按邮箱合并身份。

后端沿用精确 origin 或可信域名后缀校验原始 Host（含端口），不信任 `X-Forwarded-Host`/`X-Forwarded-Proto` 来构造回调。外层代理须拒绝未知站点并保留 Host/端口，公网使用 HTTPS；认证 URL 查询参数不得写入代理日志。新启动路由复用现有 Vite/Nginx `/api` 转发。callback 拒绝重复、关键空值、旧协议、code/error 混合、缺少浏览器事务和重放；无可信返回页面时就地显示错误和手动登录链接，不采用请求提供的任意返回目标。

- IDONE 使用 OIDC Authorization Code、PKCE、state、nonce 和签名校验；以 `issuer + sub` 识别用户，不按邮箱合并账号。
- 管理员通过 `ADMIN_SUBJECTS` 指定 IDONE 的 `sub`，不自动提升首位登录者。
- 管理员在 `/admin/channels` 按图片、文本、视频、音频四项功能配置模型白名单、默认模型和启用状态，每项功能只保留一份配置。用户在已有模型选择器中选择允许的模型，不能直接指定分组。
- 每次调用前，服务端使用已验证身份的 `issuer`、`subject` 请求 Reseller `/api/apps/keys/ensure`，使用返回的个人 Key 和默认分组。请求不包含 `app_id`、`group_id`、`key_name` 或邮箱。未验证邮箱仍可登录，但不能调用模型。
- 仅收到 `403 APP_USER_AUTHORIZATION_REQUIRED` 时发起应用内 state/PKCE 授权，经网关原生 IDONE SSO 直接返回本应用，不要求先登录 Reseller 门户。授权完成后手动继续原任务，不自动重发生成；分组权益由模型服务管理，不通过授权自动补齐。
- Key 仅在请求期间留在服务端内存；数据库只保存绑定 ID。不缓存长期 Key，也不在分组无权限、停用、额度不足时私建备用 Key。
- 模型经 `TOKENONE_BASE_URL` 的 OpenAI 兼容接口访问。已实现图片生成/编辑、Responses/Chat Completions、Ark 视频任务、语音生成路由，New API 和具体渠道的兼容性需逐项验收；云端渠道不开放自定义请求脚本和 Gemini 原生协议。
- 请求错误日志仅记错误码和请求 ID，不记录 Cookie、身份令牌、Key 或原始上游响应。

保存使用 `PUT /api/admin/channels/:capability`，接受模型列表、默认模型、启用状态、各功能调用类型与描述，以及逐模型的 `model_capabilities`（`agentEnabled` 和文本 `imageInput`）。默认模型必须在模型列表中；空列表仅允许停用。底层保留稳定的调用 ID，每个功能由唯一索引约束；其他已有数据库若存在重复功能记录，需要先人工整理，程序不自动删配置或迁移历史任务。默认模型在列表中排首位，用于没有有效个人模型偏好时的初始选择。

## 创作助手配置（待验收）

无需新增助手环境变量。部署包含本轮实现的前后端后，管理员在 `/admin/channels` 为已验收模型启用“允许创作助手调用”，文本模型按实际能力标记“支持图片理解”，再到 `/admin/agent` 开放助手并配置并发、每段模型调用次数和压缩预算及文本推理最大重试次数（新运行默认 5，0 关闭）。未设置时默认关闭，前端从服务端读取入口状态。

设置保存在 PostgreSQL，保存前展示前后变更，修订号冲突不会覆盖另一位管理员的修改。并发用于后续调度；输入、输出、调用次数、压缩和模型等待边界由新运行采用，已有运行快照不改写。文本推理的 HTTP 临时错误与断流共用单次请求的重试额度，每次真实请求计入调用预算，整个重试过程共用原等待期限，媒体和独立生成任务不自动补生成。关闭不会重发在途请求或取消已受理的独立生成任务。默认值、生效方式与待验收范围见[服务端 Agent 方案](/docs/progress/server-agent-plan)和[待测清单](/docs/progress/pending-test)。助手开关不再依赖前端构建变量；Docker 静态资源与生产部署仍按原待办验收。

## 账户、用量与历史绑定

`GET /api/account/balance` 从当前有效会话取得身份，服务端调用 Reseller `/api/apps/balance/query`，仅返回十进制字符串金额及 `USD / CNY / QUOTA` 单位。应用凭证需 `balance:read`，查询不要求模型授权，超时为 7 秒，不自动重试。顶部账户栏登录后读取一次，支持手动刷新；失败不显示为零，不影响保存或模型授权，账号变化清除旧结果。新版 Reseller 已将 `balance:read`、`pricing:read` 与用户模型授权快照解耦，需部署该版本才会生效。

`GET /api/model-pricing` 由服务端使用应用凭证读取 Reseller `/api/apps/pricing`，需部署支持该接口的 Reseller，并给应用授予 `pricing:read`、配置默认 COMPOSITE 分组。接口不依赖用户模型授权，不需要额外读取 `/groups`；CreativeOne 不再直接读取 TokenONE 公开价格接口或解析计费表达式，只校验契约并筛选后台启用的功能模型，保留本地分类和描述。

`/pricing` 页面按本地功能分类展示公开模型摘要，每个模型只保留一份条件价格表。`tiers[].prices` 的 min/max 是精确十进制字符串，端点相同显示单价，否则显示区间；按 metric、usage_key、unit 区分独立用量。partial 明确显示「价格信息不完整」，unavailable 不显示伪造零价。页面与浏览器 DTO 均无 group、paths、quotes、内部渠道、插件或倍率字段，不生成匿名报价编号。价格保留 USD，余额按接口返回的 USD/CNY/QUOTA 原样展示；不再将 USD 直接改标 CNY。金额不经 JS Number 舍入、不再次乘倍率，各计费项不相加为预估费用。服务错误只影响对应区域，应用凭证失效不清除用户登录。

价格读取保留调用方原有 10 分钟截止时间，关闭页面取消请求，不自动刷新或重试；Reseller 自行执行其契约规定的上游与操作截止时间。Reseller 的最终契约见其仓库 `docs/APP_PRICING_API.md`；部署、scope 配置及真实联调结果见[待测清单](/docs/progress/pending-test)。

Reseller 仍不提供账户汇总和用量接口。`POST /api/tokenone/account/summary`、`POST /api/tokenone/usage/query`、`POST /api/tokenone/usage/stats` 继续返回 HTTP 501 / `TOKENONE_ACCOUNT_USAGE_UNAVAILABLE`，生成流程不依赖这些接口。

部署前备份 PostgreSQL。新版为旧 Key 绑定与生成任务保留 `legacy-enhance` 命名空间，新绑定按用户、提供方和分组区分。未完成的旧视频任务拒绝跨服务查询；已保存结果保留。默认组改变继续返回 `TASK_GROUP_CHANGED`，Key 结果不明确时交管理员核验，不能删绑定重建。具体备份和回滚要求见[迁移说明](/docs/development/local-tokenone)。

## 应用公告

公告复用 Reseller 地址和应用凭证，无新增环境变量或 scope。`GET /api/announcements` 只接受指南规定的 `limit`、`offset`，服务端读取本应用公告并附上当前用户的已读状态，列表省略正文；`GET /api/announcements/:id` 重新读取详情。两个代理均要求有效业务会话，不发送 identity 或模型 Key。读取沿用应用接口现有 10 分钟调用截止时间并支持取消，不新增轮询、重试或上游内容缓存。

前端在页面加载、打开公告和手动刷新时逐页读取，汇总完整目录后统计未读，避免仅检查第一页漏掉旧公告。顶部入口显示未读数量，有未读新版本时以非阻塞的动态来信提示，可关闭；支持系统的减少动态效果偏好。关闭提醒和查看列表不计已读，成功渲染详情后调用 `PUT /api/announcements/:id/read`。写入要求当前用户会话、CSRF 及详情版本；服务端再次核验公告仍可见且版本一致，才保存阅读记录。

`announcement_reads` 以用户、Reseller 来源、公告 ID 和内容版本联合唯一，阅读时间由服务器生成；重复写入幂等，旧版本不会覆盖其他版本的记录。版本依据标题、正文和发布时间计算，正文/标题修改或重新发布重新视为未读，单独的更新时间变化不影响已读。刷新、退出重登和其他设备可读取同一账号的记录；账号变化或会话错误会清除内存状态并丢弃迟到响应。浏览器不持久化公告或已读数据。

正文使用 CommonMark + GFM 安全组件，禁用 HTML 和图片，仅允许 HTTP(S)/mailto 链接并以安全新标签页打开，代码只作为文本显示。公告下架或移出应用导致详情 404 时提示不可用并刷新列表；服务故障只影响公告区域，不伪装空列表、不触发模型授权。lab 部署与真实联调状态见[待测清单](/docs/progress/pending-test)。

## 首页与充值导航

工作台、账户栏与旧版顶栏共用 `/navigation.js` 的 `browserNavigation`，沿用现有按钮。工具校验 one_nav 后采用 Cookie 中的完整地址；公共页面在 Cookie 缺失或无效时回落平台默认首页和充值页。恢复焦点、页面重新可见、展开导航以及普通/中键点击前刷新；不自行解析 Cookie、推导渠道或新增渠道配置查询。导航偏好不参与业务身份或权限。

登录后还会异步加载同一可信分发源的 `/widget.js`，在右下角展示含首页、充值和应用目录的完整 ONE 悬浮菜单。脚本复用同一导航配置，每个文档只加载一次，路由切换持续显示；现有按钮继续保留。菜单不替应用登录或执行充值，脚本故障不影响业务页面，目录故障由菜单提供重试。

服务端 `ONE_NAVIGATION_CONFIG` 只交付可信模块地址和公开 policy，留空使用官方生产分发地址及默认 policy。lab 等非默认部署必须一起配置模块和完整 policy，示例见 [ONE 对接指南](/docs/development/one-integration)。独立渠道可按指南提供 dedicated/current，仍由模块校验且不被 Cookie 覆盖；加载失败时禁用相关链接，登录和业务页面继续可用。CSP 与模块 CORS 须按实际分发源核对。

## Reseller 截止时间与授权恢复

分组、ensure、授权发起、兑换及撤销的每次请求采用用户确认的 120 秒截止时间。余额 7 秒、价格和公告 600 秒继续沿用。前台只读请求断开会取消上游读取；后台任务、有副作用的授权请求不随页面断开取消，不新增自动重试或付费生成重放。

授权 code 在调用兑换前持久标记已消费，PostgreSQL 连接锁串行处理当前会话的授权和恢复；进程退出会释放锁，持久状态保留。兑换或随后 ensure 结果未知时保留编辑内容与待恢复状态，账户栏和授权弹窗提供「检查授权结果」，只检查 ensure。恢复成功后手动继续原任务；仍需授权时重新发起。恢复编辑内容不会删除未确认的授权记录。撤销响应未知时明确提示稍后手动再次断开，不显示成功。

轮换时在服务端 Secret 配置 `ENHANCER_PREVIOUS_APP_CREDENTIALS` JSON 数组中保留仍有效的旧应用凭证，在途事务依据凭证哈希选回原凭证。新事务使用 ENHANCER_APP_CREDENTIAL；原凭证缺失、撤销或到期时重新发起，不改用新凭证兑换旧 code。数据库只保存哈希，浏览器不接收这些凭证。原事务完成后由部署方移除旧配置。本轮未新增数据库结构或迁移，真实模型链路仍按待测清单验收。

## 存储与同步边界

PostgreSQL 保存账号、会话、渠道、Key 绑定、JSON 文档和生成任务；文件内容保存在独立持久化卷。所有业务读写按当前登录用户过滤，文件需要登录才能访问，不提供公开分享链接。

当前业务存储调整见[待测清单](/docs/progress/pending-test)：素材使用 `/api/assets` 单项接口，画布使用 `/api/projects`，设置按字段提交 `/api/settings`，提示词来源和插件记录使用对应条目接口。ID 和时间由服务端生成，浏览器只缓存服务端响应；图片/视频历史直接读取 `/api/history/:capability` 的服务端任务记录。插件私有键值仍保存在账号文档中，版本由服务端维护，不要求客户端提交 revision。

修改自动保存，账号栏通常只显示「正在保存」或「已保存」，失败时提供手动重试。刷新读取服务端结果；当前不是实时协作编辑，同一项目字段的并发提交按服务端处理顺序保存，浏览器不整份回写账号列表。不同字段及不同项目的修改会保留。

`/api/works` 和 `/api/prompts` 在后端搜索、筛选及分页。图片缩略图缓存在服务器文件卷；提示词内容首次使用后缓存在 PostgreSQL，后台按账号设置刷新，关闭页面不影响。素材 ZIP 使用 `/api/assets/export` 从服务器流式打包，浏览器下载单个文件。以上真实模型、插件与生产部署行为仍需按待测清单验收。

浏览器不再持久化业务副本，也不读取旧本地数据。离线无法首次启动；已打开页面的 JSON 保存失败仅保留在当前页面内存中，媒体上传失败直接报错。有未保存内容时关闭或刷新页面会触发离开提醒，退出登录前也会检查保存状态；继续离开会丢失未保存修改。

文件回收由服务端核对引用：移除素材/画布引用或明确请求删除后，仅回收没有其他文档和可见任务/历史引用的文件。隐藏历史或作品中的一处不一定释放文件；仍在处理的任务不会因此取消。当前没有任务保留期限、按年龄裁剪或自动清理未提交上传文件的策略。

本地 Codex/Claude Agent 的进程、连接凭据和会话仍属于当前设备，不纳入云同步，也不由 IDONE 管理。本地 Agent 默认不自动连接；在可信设备上手动连接，其本地历史仍由本地 Agent 管理。不要在公用浏览器保存本地 Agent 凭据。

## Docker 部署

服务器版只使用一个应用镜像 `<Docker Hub 用户名>/creativeone`，包含 Nginx 前端与 Node.js API；数据库使用独立 PostgreSQL 容器。对外只发布应用 3000 端口，4011 API 端口不映射到宿主机。应用以非 root 用户运行。

1. 按根目录 `.env.example` 创建 `.env`，设置 `APP_IMAGE`、`APP_PORT` 和独立 PostgreSQL 密码（当前连接串使用密码原文，请使用 URL-safe 随机密码）。`APP_IMAGE` 使用已发布的镜像标签，生产建议固定版本或 `sha-` 标签。
2. 在同一份根目录 `.env` 中填写 IDONE Client ID/Secret、Issuer、管理员 sub、Reseller 地址/应用接入凭证和 TokenONE Base URL。Compose 的 `environment` 已逐项列出这些参数，不再读取 `server/.env`，也不需要挂载配置文件。不要把密钥写入前端环境变量或提交 Git。Reseller 地址是登录必需配置；仅启用登录与同步时，应用凭证和 New API 地址可留空；应用专属 Discovery 留空则使用标准发现地址。
3. 复用浏览器可达的 Reseller origin `ENHANCER_BASE_URL=https://reseller.example.com`，设置产品 `RESELLER_APP_ID=creativeone`（默认值）。不含路径或尾斜杠，生产必须 HTTPS；登录不发送应用凭证。删除旧 `HOMEONE_LOGIN_ORIGIN`、`IDONE_APP` 和 `LOGIN_SECONDS`。后端已有内网 Reseller 地址时，部署必须改用浏览器与后端均可访问的公开 origin。
   合法访问地址沿用 `APP_ORIGIN`、可选 `APP_ORIGINS` 或可信 `APP_DOMAIN_SUFFIXES`；后缀仅用于整个域都受信任的部署，动态地址仅标准 HTTPS。所有域名共用同一业务客户端，不新增 Site 查询或 callback 列表。
   向平台交付 `appId=creativeone`、实际 `idoneApp`、`domainLabel=creative`、`launchPath=/studio`、`oidcStartPath=/api/auth/oidc/start` 和真实访问域名。产品 JSON 不包含 callbackPaths/callbackUrl；另向部署方交付各实际 origin 的完整业务 OIDC 回调和模型授权返回地址，分别在应用自己的 IDONE 客户端和 Reseller 服务应用精确登记。平台在 Reseller 登记产品与来源域名。启动路径不登记为 redirect_uri。详见 [ONE 统一登录交接](../../../handoffs/creativeone-one-auth.md)。
   启用 `openid profile email`、PKCE S256 和 `client_secret_post`，Issuer 与 discovery、ID Token 必须一致，业务 Secret 仅放服务端。`APP_ORIGIN` 仍用于媒体外链和当前模型授权固定回调；第二业务域名的模型授权问题继续保留 TODO。
4. 让服务容器能够解析并通过 HTTPS 访问 Reseller、New API 和 IDONE。本地 Caddy CA 使用 `LAB_CA_CERT_FILE` 配合 `docker-compose.lab.yml` 只读挂载并设置 `NODE_EXTRA_CA_CERTS`，不能关闭 TLS 验证。配置变更后重新创建应用容器；步骤见本地联调文档。
5. `MEDIA_DOWNLOAD_HOSTS` 支持精确主机名和 `*.域名`，多个以逗号分隔，例如 `*.volces.com,*.volcengine.com`；泛域名同时匹配根域名和各级子域名，不匹配相似后缀，非默认端口需显式配置，TokenONE 主机默认允许。上游结果域名较多时，可在根目录 `.env` 设置 `MEDIA_DOWNLOAD_HOSTS=*` 并重新部署应用，允许下载上游返回的任意 HTTPS 主机地址。默认留空，仅允许 TokenONE 主机。此规则同时影响图片和视频结果下载；使用 `*` 仍禁止非 HTTPS、URL 内嵌凭据和重定向，文件大小限制保持不变。Compose 已传入该环境变量。
6. 使用已发布镜像执行 `docker compose pull`、`docker compose up -d`；源码构建使用 `docker compose -f docker-compose.yml -f docker-compose.cloud.yml up -d --build`，也可使用 `docker compose -f docker-compose.local.yml up -d --build`（需要支持 include 的 Compose）。生产环境在外层配置 HTTPS 反向代理。镜像设置 `NODE_ENV=production`，IDONE 必须使用 HTTPS，不能直接复用本机 HTTP 联调配置。
7. 管理员登录后进入「功能模型配置」，分别编辑图片、文本等功能的真实可用模型、默认模型和启用状态，刷新页面生效。

模板只列镜像、对外地址/端口、数据库密码、IDONE 身份配置、Reseller 产品 ID 和模型服务连接参数。会话、上传限制沿用下表已确认默认值；内部端口、媒体目录和生产模式由镜像设置，无需重复填写。个人 Key 和应用默认分组由 Reseller 管理；模型调用需 `keys:ensure`，管理分组展示需 `groups:read`；余额另需 `balance:read`，价格另需 `pricing:read` 和默认 Composite 分组，公告默认可读。余额/价格读取权限不要求用户重新确认模型授权，账户汇总与用量统计继续不支持。

Compose 使用项目独立的 `postgres`、`media` 两个命名卷，数据库不发布宿主机端口；不会共享 IDONE 或 TokenONE 的数据库。服务启动时建表，不迁移旧浏览器数据。备份时需要同时备份 PostgreSQL 和媒体卷，恢复时保持一致；不要使用 `down -v` 除非明确要删除所有项目数据。

数据库镜像固定大版本为 `postgres:18-alpine`，数据卷挂载到 `/var/lib/postgresql`，由官方镜像使用版本专属数据目录；媒体卷仍挂载到 `/app/data/media`。本配置适用于新部署。已有 PostgreSQL 17 或更早版本的数据必须先备份并通过导出/恢复或 `pg_upgrade` 迁移，不能直接替换镜像或仅调整挂载路径。此配置变更不升级正在运行的本机数据库，也不修改 IDONE、TokenONE 的数据库部署。

此配置按单个后端实例设计。服务重启时，未确认结果的同步模型任务标记为 `unknown`，不会自动重发。不要直接横向扩容服务实例；异步视频任务仍可按任务 ID 查询。

镜像内用 Tini 与启动脚本管理 Nginx/API：任一进程退出会停止另一进程，交给 Compose 的 `restart: unless-stopped` 重启。上传与模型等待沿用已确认边界，不额外重试收费调用。Nginx 配置已包含在镜像中，无需挂载配置文件；`/assets/` 与 `/icons/` 缺失资源返回 404，不再返回 SPA HTML。部署后仍需验收登录、媒体上传、静态资源、流式响应和卷持久化，不能据配置检查宣称生产联调完成。

## 镜像工作流

`.github/workflows/docker-image.yml` 只发布服务器版 `creativeone` 的 `linux/amd64` 镜像，在 AMD64 Runner 上原生构建，不构建 ARM64 或启用 QEMU。沿用仓库 Secrets `DOCKERHUB_USERNAME`、`DOCKERHUB_TOKEN`，不会读取或上传本地 `.env`。Docker 构建上下文排除依赖目录、构建产物、密钥文件及数据目录。

- `main` 相关变更推送：构建并发布 `latest`、分支和 `sha-` 标签。
- `v*` 标签推送：发布版本与 `sha-` 标签，不覆盖 `latest`。
- 手动运行：发布所选分支/标签及 `sha-` 标签，只有选择 `main` 才更新 `latest`。
- Pull Request：不自动触发镜像构建；需要验证时手动运行对应分支。

前端和后端同一镜像、同一提交，不再需要 `creativeone-server` 镜像。原文档镜像和 GitHub Pages 改为仅手动触发，不参与服务器版本的自动发布。保留原有上游项目文档作参考；当前服务器部署以本页为准。

## 本地开发

IDONE 应用专属元数据通过 `IDONE_DISCOVERY_URL` 配置，应用名应与 IDONE 中创建的专用客户端一致，不得复用其他项目 Secret。显式 Discovery 的 Issuer 会单独严格核对。开发时默认仅回环地址允许 HTTP；同主机局域网 HTTP 需要明确设置 `IDONE_ALLOW_HTTP=true`，仅用于可信开发网络，`NODE_ENV=production` 时拒绝 HTTP。签名、Issuer、Audience、PKCE 等校验不关闭。

源码开发（不使用 Docker）才需要按 `server/.env.example` 创建 `server/.env`。启动独立 PostgreSQL，并在该文件配置可用 `DATABASE_URL`。在 `server` 目录执行 `npm ci`、`npm run dev`；在 `web` 目录执行 `npm run dev -- --port 3001`。Vite 默认将 `/api` 转发到 `127.0.0.1:4011`，可在 `web/.env.local` 使用 `VITE_API_PROXY_TARGET` 覆盖，`APP_ORIGIN` 应为 `http://localhost:3001`，浏览器也必须使用这个 origin。

`npm start` 面向容器注入环境变量，不自动读取 `.env`；本地开发使用 `npm run dev`。前端始终要求后端和登录，不再使用云端模式开关。

仅联调身份和存储时，必须设置浏览器可达的 `ENHANCER_BASE_URL`，可暂不设置 `ENHANCER_APP_CREDENTIAL`、`TOKENONE_BASE_URL`。相关管理/模型接口明确返回「未配置」，不会使用占位凭据或自动连接其他服务。

Reseller 仅使用新签发的应用接入凭证 `ENHANCER_APP_CREDENTIAL`，不复用旧 Enhance 凭证或管理员令牌；应用默认分组按 New API 分组名核验，用户需已有相应权益。

迁移前的本机联调记录（不代表新的 lab 环境已验收）：使用 `http://192.168.10.38:3002`（不替换原 3001 前端）、`http://192.168.10.38:8000` 的 IDONE 应用 `creativeone-local`、4013 后端和仅回环暴露的 5433 PostgreSQL。数据库由 `creativeone-local-postgres` 容器及同名持久化卷保存；媒体目录为 `server/data/media`。业务测试用户位于 AgentONE 组织，不具备 IDONE 系统管理员权限，随机测试密码仅保存在本机 `server/.env` 的 `LOCAL_TEST_PASSWORD`，不要提交或复制该文件至文档。

旧环境启动记录（切换 Reseller 时请使用迁移说明）：先 `docker start creativeone-local-postgres`，在 `server` 目录执行 `npm run dev`，在 `web` 目录执行 `npm run dev -- --host 192.168.10.38 --port 3002 --strictPort`。浏览器统一使用 `192.168.10.38:3002`，否则 Origin 和回调不匹配。现有 IDONE Compose 叠加 `deploy/idone-local.override.yml` 配置局域网端口及 Issuer；重新创建该容器时也应保留此覆盖配置与原数据库连接。

改变 Issuer 会改变 OIDC 身份命名空间：旧 localhost 的项目身份/数据不会按邮箱自动并入新 IP 身份。旧数据保留在数据库，如有实际业务数据需另行确认迁移；不要通过忽略 Issuer 来合并身份。当前已验证 IP 地址下的真实授权、回调、管理员识别和退出。

## 已确认运行边界

| 环节 | 默认值 | 到达边界后的处理 |
| --- | --- | --- |
| 登录会话 | 7 天 | 要求重新登录 |
| OIDC 登录流程 | 固定 300 秒 | 清理事务，提示手动重新登录 |
| 原页面导航记录 | 600 秒 | 缺失或过期时使用 `/studio` |
| 单个媒体文件 | 100 MiB | 上传或结果持久化失败，不自动重发模型调用 |
| JSON 请求 | 20 MiB | 返回 413，未保存修改仅保留当前页面内存 |
| 模型请求 | 10 分钟 | 结果不确定时标记 unknown，不自动重试收费请求 |
| 画布自动保存 | 原有 400ms 防抖 | 修改后触发保存，退出/重试前主动提交待保存内容 |
