## 配置准备

- 在 Reseller 启用 `creativeone` 应用，选择 New API 中已存在且用户有权使用的默认分组，启用 `groups:read`、`keys:ensure`。分组数字 ID 不沿用 Enhance；`auto_authorize_exclusive_group` 必须为 false。
- 新生成的应用接入凭证只写服务端 `ENHANCER_APP_CREDENTIAL`，不能复用旧 Enhance 凭证，不能提供 New API 管理员令牌。Docker 使用根目录 `.env`，源码开发使用 `server/.env`；不要在报告、日志或 Git 中记录凭证。
- 核验本地 IDONE Client ID/Secret、应用 Discovery、管理员 sub，以及 `APP_ORIGIN/api/auth/callback`。会话身份始终以经过验证的 issuer/sub 为准；改变 issuer 不会按邮箱合并旧用户或业务数据。不要修改在线 IDONE，也不要把 issuer 只当成地址替换。
- 已安全备份并更新本机 `server/.env` 的三个模型连接参数，文件权限保持 600；IDONE 配置完全保留。未启动/重建容器或重启后端，运行进程仍使用旧配置。旧 `deploy/tokenone-local.yml`、Enhance 联调配置和历史数据保留，不作为新服务的部署入口。

## HTTPS 与容器

从 CreativeOne 实际运行环境检查三个 lab 域名的 DNS、HTTPS 和 Caddy 根证书信任；宿主机连通不能代替容器内连通。禁止关闭 TLS 校验。

源码开发需在启动 Node 前设置 `NODE_EXTRA_CA_CERTS` 为可读的 Caddy 根证书绝对路径；不要仅写进运行时加载的 dotenv。Docker 在根目录 `.env` 填写 `LAB_CA_CERT_FILE` 为已有根证书路径，叠加 `docker-compose.lab.yml` 只读挂载：

```bash
docker compose -f docker-compose.yml -f docker-compose.lab.yml up -d --no-deps --force-recreate app
```

执行前按下一节备份并准备包含本次变更的镜像，保持原 Compose 项目名与数据卷。覆盖配置不会替你配置 DNS。重建后在容器内核验实际地址、证书路径和健康状态，检查时不要打印整份环境变量或带凭证的请求。

## 数据隔离与回滚

1. 停止应用写入，安全备份旧 `.env`、Compose 配置、镜像标签、PostgreSQL 和媒体卷；任一备份失败则停止切换。
2. 新版首次启动会为旧 `key_bindings` 和 `generation_tasks` 增加 `legacy-enhance` 提供方命名空间，保留旧记录。新绑定按 `(user_id, provider, group_id)` 更新，provider 由 Reseller 与模型服务地址组合生成，不包含凭证；凭证轮换不改变归属。
3. 新任务记录当前 provider。旧服务未完成的视频任务返回 `TASK_PROVIDER_CHANGED`，不会先获取新 Key 或向新服务查询；已保存的单条成功结果仍可读取。相同上游任务 ID 对应多条本地记录时拒绝猜测归属。分组变化继续返回 `TASK_GROUP_CHANGED`。
4. `APP_KEY_RESULT_AMBIGUOUS` 交管理员核验，不删除绑定、不创建替代 Key。旧 Key 不会自动撤销，验收后另行安排停用。
5. 回滚必须配套恢复旧代码/镜像、配置和对应数据库结构及绑定，不能只切旧镜像，也不能把 Reseller Key 用到旧模型环境。先另行保留备份后的新增业务数据，再按备份恢复，不能直接丢弃新记录。

## 行为与验收

- 服务端只向 `/api/apps/keys/ensure` 发送已验证身份的 issuer/subject，保留邮箱验证；个人 Key 不下发浏览器。`/api/admin/groups` 仍为管理员代理。
- `APP_USER_LOGIN_REQUIRED` 显示“请先登录模型服务完成账户关联，完成后回到此页重试。”并提供固定门户登录链接，新标签页打开，保留当前编辑内容。没有 return_to 或自动重试；真实 IDONE 登录由用户手动完成。
- `/api/tokenone/account/summary`、`/api/tokenone/usage/query`、`/api/tokenone/usage/stats` 对已认证请求返回 HTTP 501 / `TOKENONE_ACCOUNT_USAGE_UNAVAILABLE`，不访问上游、不返回伪造零余额。当前前端没有对应查询页面或自动请求，不作为生成前置条件。
- 配置生效后验证 groups、未关联身份的登录提示、门户登录后 ensure 与重复 Key 复用、未登录/普通用户/管理员权限、凭证撤销/应用停用/无分组权益，以及凭证不泄露。
- 图片、文本、视频、音频按实际启用的模型逐项验收；视频创建与查询已适配 New API 豆包兼容入口 `/doubao/api/v3/contents/generations/tasks`（查询追加任务 ID）。根据线上诊断，原 `/api/v3/contents/generations/tasks` 返回 404；新路径尚待部署后真实联调，不能以取 Key 成功替代模型验收。真实计费调用需相应授权。

本次 13 项后端模拟测试和 3 项前端错误状态测试通过；未运行构建、类型检查、数据库迁移、真实身份登录、模型调用或容器验收。Docker 静态资源与持久化部署仍需实际验证。完整待测项见[待验收清单](/docs/progress/pending-test)。
