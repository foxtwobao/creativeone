## 启停与凭据

在 CreativeOne 根目录启动 TokenONE：

```bash
docker compose --env-file deploy/.env.tokenone-local -f deploy/tokenone-local.yml up -d
```

Enhance 本地统一入口为 3001，开发代理转发到内部 4011 后端。CreativeOne 使用站点根地址和 `/api/apps/*`，不直连内部端口；原 `/internal/v2/*` 已停用且无兼容别名。模型仍直连 TokenONE 8080。4010 属于另一个 tokenlink 服务。

CreativeOne 本地后端使用 4013（`server/.env` 的 `PORT`），前端保留 3002；`web/.env.local` 设置 `VITE_API_PROXY_TARGET=http://127.0.0.1:4013`。默认 Vite 代理仍为 4011，只有本地配置覆盖为 4013，Docker 内部端口不变。

已备份 CreativeOne PostgreSQL 至本地 `server/data/backups/` 后启动前后端，v2 数据库结构已应用；后端 `/healthz` 和前端页面均返回 200，前端代理的受保护接口返回预期的 `LOGIN_REQUIRED`。登录和真实模型调用仍待验收。

- 新实例管理员为 `admin@creativeone.local`，初始随机密码在 `deploy/.env.tokenone-local` 的 `TOKENONE_LOCAL_ADMIN_PASSWORD`。恢复备份后，管理员账号和密码以备份内容为准。
- 数据库密码在同文件的 `TOKENONE_LOCAL_DB_PASSWORD`，仅回环端口暴露。
- `deploy/.env.enhancer-local` 和 `server/data/enhancer-local.sqlite` 是旧联调配置；当前 Enhance 使用其项目内的 PostgreSQL 配置。
- CreativeOne 的 `server/.env` 已指向本地 Enhancer 和 TokenONE；v2 需要重新配置 `ENHANCER_APP_CREDENTIAL` 为 CreativeOne 专属应用接入凭证，仅由后端持有。
- 上述环境文件均被 Git 忽略，权限为 600，不要公开其内容。
