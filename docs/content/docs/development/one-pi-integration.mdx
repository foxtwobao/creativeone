# ONE 应用 Pi 接入规范

本文供其他 ONE 应用接入 Pi 时复用。核心约定是：**加载原生 Session → 追加本次真实输入 → Pi 执行工具循环 → 保存原生增量与业务回执。** 正常对话不从请求日志重建历史，不在 Pi 外再实现规划和模型循环。

本文以 CreativeONE 已验证的 `@earendil-works/pi-coding-agent@1.5.0` 及同版本 `pi-agent-core`、`pi-ai` 为基线，含 lab 实测发现的问题。其他版本须重新验证涉及的 SDK 行为；这不是“最新版”声明，也不代表其他 ONE 已完成接入。不得修改 Pi 源码、发布包、私有方法或给依赖打补丁。

## 1. 接入边界

| 责任 | 负责方 | 实施要求 |
| --- | --- | --- |
| 对话历史、模型上下文投影、工具循环、压缩检查点 | Pi Session / SessionManager | 使用公开接口，保留原生条目；不另做一套 ModelMessage 历史 |
| 登录、用户身份、模型资格与 Key | ONE 后端 | 复用已有 IDONE / Reseller / TokenONE 接入；Key 不进浏览器或模型上下文 |
| 用户输入与业务事件投递 | ONE 后端 | 只投递新增输入；通过事务事件记录避免漏投和重投 |
| 数据读取、业务修改、生成或外部操作 | 自定义业务工具 | 校验当前账号、目标与授权，复用已有领域函数和事务 |
| 领取任务、取消、并发与运行归属 | ONE worker | 同会话串行；跨进程互斥，拒绝失效 worker 写入 |
| 页面文本、工具进度与等待入口 | ONE 前端 | 展示持久记录；不从前端消息拼出另一份模型历史 |

不要求各 ONE 复制 CreativeONE 的表名、画布工具、状态枚举或全部代码。使用应用已有的持久库、后台任务和领域服务；不为接 Pi 新造中心化 Agent 服务、跨应用工具协议或通用工作流引擎。身份和模型授权继续遵循 [ONE 对接指南](/docs/development/one-integration)。

## 2. 正常输入只走一次 Session 入口

前端提交本次新输入、会话 ID、提交 ID 和业务引用；服务端验证归属后恢复该会话的原生 Session。不得每次把整份 UI 对话重新灌入 Pi，也不得同时投递“用户消息”和一份内容相同的业务消息。

运行上下文只补充模型能力、已选择 Skill、创作状态等必要业务数据，不再复制同一份用户目标。不同真实提交即使文字相同也不能按正文去重；已持久化的旧输入不为简化展示而改写。

以下只展示消息入口；调用前已经完成认证、运行领取、受控 Session 构造和持久化接线，不是可直接投产的完整宿主：

```ts
await session.sendUserMessage(userInput, { expandPromptTemplates: false });
```

包含结构化业务数据时可以使用公开 `sendCustomMessage`。选择一种入口投递该输入，不再额外补一句“继续处理”：

```ts
await session.sendCustomMessage({
  customType: "one.business_result",
  content: JSON.stringify(receipt),
  details: { eventId },
  display: true,
}, { triggerTurn: true });
```

一批待投递事件只启动一次：前面的事件以 `triggerTurn:false` 追加，最后一个真实事件启动本轮。消费标记与对应原生条目的保存必须在同一事务提交，禁止分两次提交后依赖重启猜测是否重复投递。

有新用户输入就走 Session 输入接口；`session.agent.continue()` 仅用于已正确恢复、没有新输入且允许继续的尾部，不能用来跳过缺失工具结果、具体授权或未知请求。一次低层 `agent_end` 不必然表示 SDK 已最终停止；前端完成状态结合宿主业务状态与 SDK 的 settled 语义确定。

## 3. 一份模型历史，稳定的消息身份

数据库保存 Pi 原生 header 和 entries，内存 Session 从中恢复。共享服务不同时把本地 JSONL 与数据库当作权威；采用数据库时可使用公开 `SessionManager.inMemory(cwd, options, entries)`，不直接赋值 `session.agent.state.messages` 代替历史恢复。

原生条目保存原始 JSON 文本、顺序、entry ID 和 parent ID；账号、线程、运行及索引字段另存。已保存条目不重新格式化、排序参数键或转成业务 DTO 后还原。请求快照、原始响应、usage 和业务回执用于审计及有限恢复，不是第二份对话历史。

| 标识 | 用途 | 不应混用为 |
| --- | --- | --- |
| `userId` / 租户标识 | 后端确认的数据归属 | 模型参数中声称的账号 |
| `threadId` | 一条业务会话 | 一次模型请求或全部用户共享 Session |
| `turnId` / `runId` | 本次用户操作及其运行 | 原生条目 ID |
| `itemId` | 前端展示消息 | 工具调用 ID |
| 原生 `entry.id` / `parentId` | Pi 历史身份与顺序 | 数组长度、正文或整对象比较结果 |
| 提供方 `responseId` | 已保存响应的稳定身份 | thinkingLevel、时间、usage 等可补充元数据 |
| Pi `ToolCall.id` | Pi 工具调用与结果配对 | 未经适配就直接发送的上游 `call_id` |
| 提供方 `call_id` | 提供方协议中的调用配对 | 不带运行归属的全局业务操作 ID |
| `submissionId` / `eventId` | 输入或事件去重 | 每次重试新生成的 ID |
| 执行令牌 | 当前 worker 的写入资格 | 用户身份或生成授权 |

提供方 ID 的匹配必须限定所属用户、会话、运行及提供方；若当前协议不提供可用稳定响应 ID，应明确建立响应与原生条目的持久关联，不能猜测相等。

**禁止用 `JSON.stringify(a) === JSON.stringify(b)` 或深度对象相等来判断一份响应是否已进入 Pi 历史。** Pi 可以在原始模型消息上补充 `thinkingLevel`、`providerThinkingLevel` 等元数据。正常续聊完全不需要这类判断；确有中断时只检查未完成尾部的稳定身份。

Pi 的工具 ID 可能包含提供方调用和输出 item 的复合标识。交由已选提供方适配器转换，宿主只维护明确的领域映射，不自行拆拼整段上游对话。

## 4. 异常恢复只处理未完成尾部

| 中断位置 | 恢复动作 |
| --- | --- |
| 尚未发出模型请求 | 按原提交去重后继续正常输入流程 |
| 请求已发出，完整响应未持久化 | 标记未知，保留部分输出，不因重启自动重发 |
| 完整响应已保存，Pi 尾部尚未保存 | 仅补入这份确实缺失的未完成响应，以稳定身份核对 |
| 决定已保存，工具尚未执行 | 校验当前身份、来源和授权后处理原调用；不让模型重新生成参数 |
| 业务回执已提交，缺 Pi 工具结果 | 从该真实回执补齐尾部；不再执行业务修改 |
| 工具结果已经完整 | 直接使用 Pi 历史；不重放已完成步骤，不追加第二份结果 |
| 等待用户确认或后台任务 | 相应事实到达后追加真实结果，再继续 |

不得扫描所有 finished steps，把每份“看起来不相等”的 assistant 再插回历史。不得每次输入都遍历旧记录做全历史修复，也不得用一句“继续”掩盖未完成的操作。

参数校验失败只向模型提供一份权威结果。SDK 原始校验信息可以保留供诊断，但不能把 SDK 错误结果和同一调用的业务错误结果各追加一次。已有回执优先复用；全部工具结果都应能追溯到原调用。

Pi 提供 `toolCall.argumentsError` 时，直接保留其 JSON 解析原因，不把解析后的空对象再解释成缺少业务字段。`toolResult.isError` 也不能一律标成参数错误：前序操作等待确认或结果时，后续调用尚未执行，应使用执行器已知的暂停状态和原阻止原因。不得手工修补模型 JSON，或为美化展示改写旧历史、工具定义和 Skill。

`pi-coding-agent` 的交互界面及自定义渲染接口面向终端；Node/Bun SDK 提供消息、工具结果和流式事件。网页由应用消费这些公开数据并渲染，错误原因沿用原结果，不再按展示需要猜测或重分类业务事实。

用户回答只追加一份真实输入。应用仍保存提问的业务回执供审计和展示，但不把相同答案再作为 `operation_result` 投递。其他后台操作的真实完成结果继续正常投递，不因此删除它们的业务事件。

展示中，运行 `completed` 表示本轮结束；浏览器操作 `queued` 表示请求已发送，不能展示为执行成功。未知错误保留原文或错误码；只有真实参数校验失败才反馈字段问题，不新增模型目标达成判定流程。

## 5. 工具与业务授权

工具名称、描述和参数定义维护一份来源，同时生成模型 JSON Schema 与服务端校验；复杂组合规则必须在 schema 或明确字段反馈中可见。严格 schema 与语义校验均不能代替账号授权。

Pi 1.5.0 的参数校验可能进行类型转换。读取类普通参数沿用公开 `validateToolCall` 和实际执行回调给出的规范化值，例如 `includeImages:"false"` 可成为布尔值 `false`；禁止执行前把参数换回原始值。业务入口继续校验规范化后的语义、账号与资源归属，原始参数保留在请求日志和原生历史。读取工具清单由宿主明确维护，不按模型声明或工具名称前缀猜测。

写入和授权类继续对原始参数严格校验，不能把字符串 `"true"`、数字 `1` 或数组当作用户明确的布尔授权；`null`、省略和默认值必须保持业务既定语义。不要把保护授权的原值规则一概套到普通读取选项，也不要为修复读取而全局接受类型转换。

业务要求整轮无效零执行时，在完整 assistant 到达后统一预检，再允许工具执行；不能已经执行有效兄弟调用后才发现同一决定的其他参数无效。反馈字段路径、预期类型和允许值，在已有模型调用预算内纠正，不新增隐式纠错循环。

整批预检与中断恢复使用相同的 Pi 读取参数规则；否则正常执行能读取，重启后却可能因原参数与规范化回执不同而误报冲突。真正无效的数组仍拒绝，混合批次有无效写入时仍整批不执行。前端直接展示已保存的字段问题；查找节点返回 ID、类型和标题不等于成功读取正文，验收必须检查真实正文回执，不能以运行 completed 推断目标已核实。

不要仅因等待工具不在列表末尾就把合法参数判为整轮错误。按 Pi 工具顺序执行，进入业务等待后阻止剩余副作用并保存未执行原因，真实结果到达后继续原生 Session；等待不会授权后续操作。

上游 strict 必须核对**实际出站载荷**。不能把 Zod `.strict()` 或某个本地配置当成已发送 `strict:true`。CreativeONE 的嵌套联合结构无法全部经过 Pi 1.5.0 的 require 转换，使用公开 Responses `onPayload` 钩子写入同源闭合 schema；其他 ONE 先验证自己的真实工具结构，不必照搬这个适配。不得静默放宽 strict、修改 Pi 转换器或换调用协议。

生成、付费、删除、发布等操作复用应用已有的具体确认：保存原操作、参数、目标及来源版本；批准后执行这份原操作，变更后使旧授权失效。模型说“用户已经同意”、Skill 内容或历史摘要都不能生成授权。

业务修改与业务回执在同一事务提交；外部副作用使用已有持久任务和明确的不确定状态。内部回执幂等不能证明外部服务一定只执行了一次，结果未知时不得通过换 ID 再发一次来“恢复”。

## 6. 保存屏障与 SDK 默认行为

决定必须先持久化，再执行工具；下一次模型请求和运行结束前也要保存原生增量。事件消费标记、业务状态与条目追加要有明确的事务边界。

自定义模型传输层转发 Pi 原生文本、思考和工具流事件，不先吞完整响应再重建只有 `done` 的流。最终完成事件须等待完整响应与用量持久化；流迭代中的应用异常必须保留原异常，不能被 SDK 的通用错误消息替换，否则授权失效和来源变化会丢失原恢复语义。网页实时投影继续使用稳定消息 ID，最终以持久记录为准。

Pi 1.5.0 已验证的异步屏障是 `session.agent.subscribe()`；`session.subscribe()` 不等待异步回调，适合 UI 事件，不得把它当作数据库提交屏障。不能仅写 `session.subscribe(async () => save())` 就宣称已实现“先保存后执行”。保存失败后使内存 Session 失效，停止后续请求和工具，下一次从持久状态恢复。

每种策略只设一个负责方：

| 策略 | 要求 |
| --- | --- |
| 模型重试 | 沿用应用已有持久策略；若宿主负责，则关闭 SDK 自动重试与提供方内层重试，避免次数相乘 |
| 调用与费用预算 | 所有真实模型尝试、摘要和重试都计入；不中途清空原运行用量 |
| 输出上限与思考配置 | 保持应用明确配置；不直接照搬 Pi 默认 maxTokens 或其他 ONE 的 thinking 设置 |
| 压缩 | 由 Pi 投影与检查点处理；若宿主按既有预算触发，关闭冲突的默认自动触发，不手写摘要替换历史 |
| 截断与拒绝 | 保存原响应并停止该决定的副作用，不执行“外观完整”的截断工具调用 |
| 缓存预热 | 按应用明确策略配置，不让 SDK 默认预热产生未计入策略的额外请求 |

CreativeONE 为保持“不传正常输出上限”使用公开低层 Responses `stream`；仅在产品有同样要求时采用。使用 `streamSimple` 时须验证其实际 maxTokens 行为。协议和提供方来自配置，不按型号名称或失败结果自动切换。

自定义 `streamFunction` 不能丢弃 Pi 的请求选项：传递原生 `sessionId`、`cacheRetention`、取消信号和观察回调，本站的 Key、持久重试、调用预算及实际工具契约在这一层明确覆盖。不要为稳定路由另造一个每轮变化的缓存 Key，也不要把摘要请求与普通对话硬套同一缓存策略。

上下文触发量使用 `session.getContextUsage()`；它采用有效的上游用量和原生投影，压缩后尚无新响应时可能返回 `tokens:null`，不能拿旧用量或历史文件大小补成已超限。近期保留预算直接设置 Pi 的 `keepRecentTokens`，交由 Pi 选择边界并保留完整工具轮次；摘要额度通过请求输出上限及实际 `usage.output` 校验，不再以中文字数或 UTF-8 字节数冒充 token。明确上下文拒绝使用 Pi 公开 `isContextOverflow`，保留应用既有的持久恢复次数和未知状态策略。

图片按原生 `image` 内容块交给支持识图的模型，Base64 是传输编码；不得用 `JSON.stringify(messages)` 的字节数把编码长度计入文本预算，也不能为降低估算而删改已保存的图片和历史。

本文不规定统一的超时、并发、重试次数、保留量或调用上限。各 ONE 沿用自己的已确认配置；需要改变时明确适用环节、默认值和失败处理，取得产品方确认。

## 7. Skill、规则与缓存

使用显式工具白名单和受控 ResourceLoader。产品用的规则、Skill 和资源来自受控业务配置；不得默认读取服务进程的个人认证目录、任意项目 AGENTS.md、扩展、终端或文件工具。

规则指导模型行为，工具代码保证权限。开发仓库的 AGENTS.md 约束开发者，不能直接当成产品 Agent 的全部系统提示词。Skill 按当前账号和版本读取，需要时作为工具结果或新事件追加；不每轮把所有 Skill 正文塞进 system。

同一会话固定系统规则、工具定义及顺序的快照。阶段、画布变化、模型能力与用户补充通过新事件进入尾部；正常续聊不改旧历史、不频繁重组 system、不重新序列化已有调用参数。附件使用确定的所属文件内容，不把会变动的临时 URL 写回历史。

用户明确换模型、规则或工具版本，以及正常压缩，都是需要说明并验证的上下文边界。前缀稳定只能证明应用没有无故破坏前缀，实际缓存命中与费用仍需提供方 usage 验证。

## 8. 多用户、同用户与部署

每个活动会话独立 Session、工具执行闭包和取消信号。凭据必须按已验证身份选择，不得让带当前用户状态的运行对象跨账号共享；只读工具定义或无用户状态的基础设施可复用。

同一会话只有一个活动执行者；相同提交复用原运行，提交内容变化拒绝，其他输入按明确的队列或忙碌策略处理。同账号的不同会话可以并行，但是否实际并行由后台单账号及全局上限决定，不能只看进程内 Promise 数量。

跨 worker 使用数据库锁或应用已有的等价互斥机制领取任务；执行令牌阻止失效 worker 的迟到写入，原生追加校验预期位置。同账号不同会话操作同一业务对象时，领域版本与来源校验仍然生效；冲突后放弃未执行的旧决定，不覆盖他人修改。

有画布、文档等编辑界面时，视图偏好与内容编辑分别约定版本语义，不能让平移、缩放保存因 Agent 更新内容而阻塞整个页面刷新。云端结果到达后，只合并确认不冲突的本地增量，不把旧整份内容反写为用户编辑；同一对象的真实冲突仍保留本地修改并阻止覆盖。同步成功后清除同一资源的旧错误。多任务并发完成与用户操作必须交错验收，不能只测任务是否在数据库成功。

可以独立进程或容器部署，但只有一套任务领取职责。独立模式下 API 不再扫描 Agent 任务，并延迟加载 Pi 执行模块；仅把执行函数挪进容器、API 仍静态加载或重复运行执行器，不算完整隔离。独立容器不代替租户权限或数据锁，也不要求每个账号一只容器。若产品确需执行用户代码，应另行确定执行隔离，不能把普通业务工具进程当作代码沙箱。

使用实际 Node 版本、系统镜像、CA、数据库和媒体卷验证部署，不用宿主测试通过代替容器验证。停止和重启不应自动重发未知模型请求。

## 9. 变更与故障处置

新应用按新格式实现，不为不存在的旧会话写兼容或迁移层。只有明确保留已有真实会话时，才停写、先备份并校验、再一次性迁移；消息存储版本、Pi session 版本与前端通信版本分别管理。未知版本、损坏顺序、错误归属或配置冲突拒绝覆盖。

发现重复上下文时，先保留失败请求与原生条目并备份，再定位具体错误副本。需要保留原始审计历史时，通过公开 `SessionManager.appendContextEdit(targetId, null)` 追加排除记录，重新验证投影；不直接删库、重写旧条目、重置用量或在每次请求时静默过滤重复记录。修复完成后恢复明确继续入口，不能自动触发收费调用。

诊断至少能关联账号、线程、运行、展示 item、原生 entry、提供方响应、工具调用和业务回执。保存原始 HTTP 状态、错误体、完整响应与 usage，供受控诊断；普通日志和面向用户接口不暴露 Key、Cookie、敏感提示词或供应商内部配置。原始请求与会话备份按私密业务数据管理。

### 已发生的反例：元数据差异导致重放

CreativeONE 在提问后继续时，用请求日志的 assistant 与 Pi 已持久化的 assistant 做整对象比较。Pi 已补充 `thinkingLevel`，宿主误判历史缺失，把已完成的 read / Skill / question 决定再追加了一遍。下一次请求含重复 `function_call.call_id`，上游返回 400 `duplicate function call_id`。

正确修复是删除已完成历史的重放逻辑，正常输入直接启动 Session，恢复只核对未完成尾部的稳定响应 ID。不能靠移除 thinkingLevel、递归删掉“不同字段”或放宽对象比较继续维持全历史扫描。

## 10. 接入验收

验收检查实际提供方请求载荷，不能只测页面显示或让模拟服务无条件接受请求。

| 场景 | 必须证明 |
| --- | --- |
| 普通输入与下一次续聊 | 一次输入只进入 Session 一次，旧原生条目不变，无额外伪造的“继续”消息 |
| 提问 → 用户回复 → 跨进程继续 | SDK 给消息补充 thinkingLevel 等元数据后仍不重放；工具调用与结果配对唯一 |
| 提供方协议校验 | 模拟上游拒绝重复 call_id、重复结果或未配对结果；不能用宽松 mock 掩盖错误 |
| 提供方实际载荷 | 原生复合 ID 转换正确，工具 schema / strict、输出上限和思考配置符合约定 |
| 参数错误与混合决定 | 原始值不被强制转换为授权；无效决定零副作用，每个调用只有一份权威反馈 |
| 确认与后台等待 | 未批准不执行；批准执行原操作；拒绝、来源变化、迟到回调不绕过确认 |
| 保存失败与 SIGKILL | 覆盖决定保存前后、业务事务提交前后、结果保存前后；重复恢复不重复副作用，未知请求不重发 |
| 账号与并发 | 两账号、同账号两会话、同会话重复提交及两个 worker 竞争；上下文/文件/写入隔离，实际槽位符合配置 |
| 多结果回填与页面编辑 | 并发结果全部保留，缩放/视图保存不误阻塞刷新；不冲突的本地增量可继续，同对象真实冲突不被自动覆盖，恢复后旧错误清除 |
| 压缩与恢复 | 原条目保留、调用/结果不拆散；摘要失败不覆盖历史，无效摘要不被当成可复用成功响应 |
| 取消、刷新与订阅重连 | 失效 worker 不再写入；同一 item 不重复物化；页面关闭不决定后台任务生死 |
| 上下文修复 | 先备份，只追加对指定错误副本的 context_edit；修复后真实 SDK 载荷不含重复调用 |
| 真实模型与目标部署 | 同模型实际任务、缓存用量、费用及实际运行镜像分别验证，不以离线通过宣称能力提升 |

定位历史或协议问题时，可先用真实 Session 和提供方适配器生成载荷，在公开 `onPayload` 处截停，并令 fetch 禁止联网；确认调用唯一、结果配对和前缀后再进行真实联调。离线预检不能当成模型质量或实际成功的证明。

## 11. 可复制到其他仓库 AGENTS.md 的规则

其他 ONE 可将本文放入自己的文档目录，在项目文档索引中登记，再加入以下规则。实施者仍须读取对应版本的 SDK 声明及文档，不能只复制 CreativeONE 的工具和存储实现。

```text
- 接入或修改 Pi 前，先阅读项目文档索引中的“ONE 应用 Pi 接入规范”。
- 只用公开 SDK，不修改 Pi 源码、发布包、私有方法，不给依赖打补丁。
- 正常流程只恢复原生 Session、追加真实新输入、让 Pi 执行工具循环。
- 不从 UI、请求日志或 finished steps 重建模型历史，不额外伪造“继续”。
- 不按 assistant 整对象相等判断漏存；SDK 元数据不参与历史身份判断。
- 中断恢复只核对未完成尾部的稳定身份和真实回执，不重放已完成操作。
- 每个调用只反馈一份权威结果；读取沿用 Pi 规范化参数，写入/授权严格校验原值，业务工具保证账号和具体授权。
- 用户回答只投递一次，展示回执不重复注入答案；直接传递原生流事件和原异常，完成前先持久化。
- 决定先保存后执行；保存失败停止 Session；未知在途请求不因重启重发。
- 同会话串行，跨账号隔离，跨 worker 互斥并拦截迟到写入。
- 普通续聊保持历史前缀；修复先备份，再追加指定 context_edit。
- 重试、预算、压缩各有唯一负责方，不静默改变应用现有边界值。
- 必测提问回复后的元数据差异、真实载荷重复 ID、事务故障及多用户并发。
```
