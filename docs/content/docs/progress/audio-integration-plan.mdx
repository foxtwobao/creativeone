# 音频工作台与画布接入方案

状态：首版代码已实现，音频专项、既有图片/视频回归及模拟接口浏览器检查已通过；真实账号、模型、价格、下载域名和编码播放仍待联调。独立音频工作台与画布已同时接入，验收详情见[待测清单](/docs/progress/pending-test)。

依据：[音频总览](https://doc.tokenone.work/web/#/688394820/172712496)、[Gemini TTS](https://doc.tokenone.work/web/#/688394820/172712497)、[Lyria](https://doc.tokenone.work/web/#/688394820/172712498)、[Suno](https://doc.tokenone.work/web/#/688394820/172712499)，以及用户提供的表单参考与统一工作台体验要求。模型实际可用性与价格以目标账号和接口为准。

## 1. 首版范围

| 功能 | 交付内容 |
| --- | --- |
| 独立音频工作台 | 新增 `/audio` 页面和导航；居中创作、本次结果在下方，历史统一进入「我的作品 / 生成任务」，沿用图片、视频工作台布局与主题 |
| 单人配音 | 完整配音文案、预置音色和灵感示例，生成 WAV |
| 双人配音 | 两个角色及各自音色、带角色名的剧本，生成 WAV |
| 音乐与歌曲 | 音乐描述、可选歌词、歌曲/纯音乐选择；Lyria 输出 MP3，Suno 按实际响应保存 M4A |
| 多版本作品 | 同一任务展示全部结果，分别试听、下载和添加到画布 |
| 作品管理 | 可选名称、任务级改名、复用参数再次创作、收藏、上传音频；与「我的作品」共用数据 |
| 画布生成 | 恢复音频生成与再次生成，共用工作台的请求构造、校验和服务端执行流程 |

文档列出的接入型号为 `gemini-3.8-flash-tts`、`lyria-3.5`、`lyria-3-pro-preview`、`suno-v6-mini`。后台明确配置每个模型的调用类型并启用，前台不按名称推导能力、合并型号或创造友好名称。未配置音频模型时显示不可用说明，管理员仍可进入模型配置。

首版不做语音识别、声音克隆、参考音频生成、翻唱、续写、分轨、音频编辑、实时语音或两人以上配音。不增加 PCM 选项、转码服务、波形编辑器、批量生成、音色试听生成、流式输出或音频插件系统。已有视频参考音频功能保持其原有规则。

## 2. 工作台交互

- 沿用统一工作台主题和管理入口，使用顶部紧凑创作表单，页头合并标题和操作，桌面并排放置简短字段；下方仅显示本次受理任务的进度和全部返回版本，不在创作页重复加载整份音频作品库。模型区使用后台返回的完整模型名、可选描述及公开价格，不固定四张卡片、不自行添加厂商徽标。
- TTS 显示单人/双人、音色和完整文案或剧本，不单设风格说明；朗读要求直接写入文案，例如「请用温柔自然的语气朗读：……」。提供灵感示例，双人示例使用当前角色名；替换非空文案前确认，保留音色与角色配置，填入示例不提交生成。画布在原有配音文案中填写要求，不在参数浮层另加正文。音乐显示歌曲/纯音乐、描述、可选歌词，模式使用实心选中态、勾选和含人声/无人声说明。名称仅作作品展示，不发给上游作为生成参数。
- 复用一个配音表单和一个音乐表单；切换模型保留相应输入。Lyria 两型号与 Suno 共用音乐输入，不为每个模型保存一套草稿。未提交正文只在页面内存保留，参数偏好沿用现有账号设置，不引入浏览器持久化。
- 单人/双人使用与音乐模式一致的实心选中态和勾选，往返切换保持切换控件的位置和宽度；双人角色配置在下方独立区域展示。双人角色名需非空、不重复，明确提示剧本的角色标记对应关系；不自建完整剧本语法或自动修正台词。语气、语速要求作为文字提示，不承诺精确数值控制。
- 音色下拉保留接入文档列出的 27 个英文 ID，附上 Google 官方预置音色风格的中文说明并支持中英文搜索；中文只作风格参考，不承诺实际声音特征，提交仍使用原英文 ID。
- 单人默认音色与共享配音默认值保持一致，使用清单内的 `Kore`；读取个人偏好时验证音色仍在清单中，无效值使用默认音色，有效的个人选择保留。
- 生成按钮使用「生成配音」或「生成音乐」，放在长正文/歌词之前并采用紧凑宽度，滚动编辑时操作区吸附顶部；按钮右侧直接展示接口原币种价格、区间和计费单位，多项计费及档位条件分别保留。附近展示输出格式、数量/时长不保证及计费说明；缺少报价显示暂不可用，不伪造零价或按次总价。
- 同一次创作在提交期间防止连点，受理后保持按钮和表单锁定，按钮随任务状态展示生成中、已完成或失败等结果；首次读取进度及状态查询失败时也不解锁。用户通过「新建创作」明确重置表单和按钮，原任务继续后台处理；提交结果未确认时先确认原提交，不允许新建绕过。
- 历史、上传与管理统一放到「我的作品 / 生成任务」，工作台入口自动筛选音频，切换作品/任务保留类型筛选；音频分类按全部/音乐/配音读取生成时保存的调用类型。上传音频只进入全部，不猜测分类。单任务内列出多个版本，作品名称为任务级名称，版本使用简单序号，不做独立版本改名体系。
- 移动端沿用同一纵向创作、结果布局，不再设置独立的创作/作品切换。播放器点击后才加载原媒体；开始播放另一条时暂停当前播放，不做全站播放器。
- 统一管理页复用分页和轻量任务状态；工作台与画布任务抽屉仅在当前任务进行中轮询轻量状态，状态变化后读取完整结果，页面隐藏时暂停。Suno 播放受浏览器实际编码支持影响，播放失败显示说明并保留原文件下载，不自动转码或改后缀。

截图里的固定人民币价格、24 小时保留、8000 字限制和一次调用只计费一次均不作为本项目规则。文件沿用现有引用与清理机制，不增加定时删除策略。

## 3. 最小协议适配

沿用后台图片/视频逐模型配置方式，增加一个音频调用类型映射：Gemini TTS、Lyria、Suno。使用简单共享类型、请求构造和校验函数，不建立可扩展适配器注册中心、动态表单 DSL 或多供应商路由层。

三个类型都调用 TokenONE `/v1/chat/completions`，显式 `stream: false`。服务端按已验证用户身份获取应用默认分组 Key；音频仍归入音频任务，不能因为复用 Chat 路径而开放其他文本接口权限。

| 类型 | 发送内容 | 首版不发送 |
| --- | --- | --- |
| Gemini TTS | 一条 user 文本直接使用完整文案或剧本，画布按原有方式追加连线文本；`audio.format: wav`；单人音色或双人 `speakers`；`output_format: url` | 独立风格说明的自动拼接、旧 `input`、顶层 `voice`/`instructions`、`speed`、不支持的编码 |
| Lyria | 一条 user 文本合并描述、纯音乐要求及可选歌词；`output_format: url` | TTS 参数、独立歌词字段、数量、秒数 |
| Suno | 一条 user 文本合并描述和可选歌词；纯音乐时 `instrumental: true`，歌曲时省略该偏好 | `output_format`、TTS 参数、`n`、`duration` |

不暴露 temperature、URL/Base64/both 等技术选项。首版只请求并处理约定的 URL 交付；TTS/Lyria 响应附带的内嵌音频忽略，只有内嵌音频而没有有效链接时仍拒绝。异常返回不能当作成功文件，不为未请求的格式增加通用兼容层。

前后端共用业务参数校验和请求构造，服务端仅发送当前调用类型允许的字段。调用类型、创作模式及表单原始输入随不可变任务请求保存，实际发送正文由这些输入构造；内部展示与归属字段发送上游前移除。历史复用读取快照，不反向拆解合并后的文本，不使用当前模型配置猜测过去参数。模型已停用时要求重新选择，不自动替换后提交。

## 4. 任务与结果保存

复用 `generation_tasks`、现有 PostgreSQL 领取锁/执行标识、后台扫描、媒体下载和文件卷。不引入 Redis、独立消息队列、工作流引擎、下载任务表或音频历史表。

1. 音频提交先保存任务，再返回受理结果，由现有工作器执行。工作台每次明确生成携带提交标识，服务端按用户与标识去重并比较请求快照；同标识不同内容拒绝。只在现有任务表补必要字段和唯一约束，不改造成全站幂等框架。画布沿用现有生成标识和权威快照。
2. 同一次提交在等待受理时复用标识；界面阻止重复点击。响应丢失后先查回原提交或按原标识重发受理请求。刷新后读取服务端任务列表，不自行再次提交；不承诺浏览器状态完全丢失后的新标识仍能自动识别重复意图。
3. 音频任务截止及非流式调用的响应头、正文等待统一为用户确认的 15 分钟，避免底层 HTTP 客户端默认等待先终止；超时保留未知结果，不自动重新生成。检查 HTTP 状态、响应错误、正文错误、正常结束标记及有效音频结果。上游 Chat ID 只用于排查，不能作为可轮询任务 ID。
4. 在下载前保存上游响应。TTS/Lyria 使用成熟 HTML 解析库提取音频地址；Suno 优先使用完整 `data[]`，缺失列表时按其文档解析正文链接。只在实际需要时增加成熟解析库，不手写 HTML/Markdown 底层解析，不把上游 HTML 插入网页。
5. 按完整 URL 去重，保留签名查询参数。复用媒体下载白名单与重定向规则，不附带 TokenONE Key；联调确认实际下载域名，不放宽成任意 URL 下载。检查文件为有效音频，沿用 `music-metadata` 读取时长，下载文件名按实际格式确定。
6. 一个任务保存有序音频结果列表。逐项记录已保存文件及未保存项错误，后续单项失败不丢弃先前成功文件；每次成功保存及时持久化，恢复时跳过已保存项。保存在现有任务结果中，不拆独立版本实体或文件恢复服务。
7. 全部保存成功后任务完成；部分未保存时沿用需处理状态，界面仍可播放和下载已保存项。只有已有完整上游响应且存在未保存结果时才提供「恢复保存」，操作不重新调用模型；临时链接过期后不能保证恢复成功。
8. 上游执行结果未知时保留任务，停止自动提交。明确收到生成失败与传输结果未知分别展示；用户主动再次生成是新任务并提示可能重复计费。关闭页面不等于取消、退款或停止后台处理。

不宣称应用去重能保证上游恰好一次计费。服务端重启后的恢复沿用现有执行归属：完整响应已保存时允许恢复文件保存；调用已发出而响应未保存时不能自动重新生成。

在现有任务表中增加可编辑的作品名称，补单项改名接口和账号归属校验；不修改原始请求快照、不新增作品目录表。收藏和上传复用素材单项接口，补齐其音频类型；工作台、我的作品、管理任务共用结果解析。收藏关联任务及具体文件，不复制文件；生成作品以任务标题为准，收藏保留自己的素材标题，改名不级联重命名收藏或画布节点。删除/移除沿用现有语义，仍被画布、任务或收藏引用的媒体不能误删。

## 5. 画布接入

- 恢复音频生成入口，修正音频节点落入视频模式的问题。沿用节点音频设置与提示词入口，补齐当前协议支持的参数；不重做画布或加入按连线自动执行。
- 配音与音乐只读取文本创作输入，图片、视频、已有音频不会作为本次音频模型的参考素材发送。节点使用自身保存的模型、模式及参数，不能被工作台当前选择覆盖。
- 生成前保存目标节点与生成标识，由服务端已保存节点构造权威请求，沿用账号校验、旧结果保护与重复受理处理。
- 一节点对应一份音频，按响应顺序选首个已保存成功项作为本次默认结果，后续恢复不会自动更换该结果。节点提供查看任务全部版本入口，其他版本由用户选择后添加为新节点；不在首版增加节点内多版本切换或音频槽位体系。
- 节点删除、重新生成或等待期间编辑时，迟到结果保留在原任务中，不能恢复已删除节点或覆盖新生成。挂载只更新结果字段，保留标题、位置、尺寸和正在编辑的输入。
- 必要的新增音频参数同步纳入现有保存、撤销与归档字段；引用和真实文件信息由服务端校验。不新增归档格式兼容或旧数据迁移兜底。

## 6. 边界与实施顺序

沿用现有上传/下载大小、生成超时、扫描与轮询间隔，不照搬教程示例超时或截图输入上限，不新增自动重试、并发或保留期限。实现中如必须新增或改变边界值，先说明适用环节、默认值和失败处理并取得确认。

实施顺序：共享音频协议与后台模型配置 → 现有任务执行器及结果保存 → 独立音频工作台和作品管理 → 画布恢复 → 定向验证及真实联调。前四步共同构成首版，不能以先完成画布为由取消工作台。

修改范围限于音频所需的后台配置、任务受理/执行、结果/素材、工作台路由和导航、画布相关代码；不重构图片/视频任务体系，不修改或部署 TokenONE 等关联项目，不自动启用实际账号模型。

| 验收项 | 通过标准 |
| --- | --- |
| 工作台与模型 | 页面可独立使用，后台配置决定可选模型；配音/音乐参数匹配实际协议 |
| 单人/双人、歌曲/纯音乐 | 请求字段正确；角色配置明确；模型往返切换不会串参数或丢表单输入 |
| 去重与中断 | 同提交只创建一个本地任务；响应丢失、刷新、关闭页面及进程中断不盲目重提 |
| 多版本与部分失败 | 全部返回项保留；成功文件可用；恢复只保存缺失项，链接过期明确失败 |
| 作品数据 | 改名、收藏、参数复用、分类与跨设备结果一致；不依赖浏览器数据库 |
| 画布 | 单结果节点、全部版本入口、再次生成、迟到结果、删除/撤销及导入导出归属正确 |
| 隔离与媒体 | 跨账号任务和文件不可访问，下载不泄露 Key，非法结果不确认成功 |
| 界面与回归 | 明暗主题和窄屏可用，原媒体按需读取；现有图片/视频入口及任务行为不回退 |

使用模拟上游与隔离数据库验证关键失败场景，不为简单布局增加实现镜像测试；真实模型、实际价格和目标浏览器播放须另行联调。按项目规则不执行构建或语法检查。实现后更新 CHANGELOG 并把完成事项转到待测；用户确认通过后才更新正式功能说明。

## 7. 过度设计复核

结论：按以上范围实施，没有必要引入新的平台层；复杂度集中在现有功能缺口，属于实现已确认需求的必要工作。

| 设计项 | 判断及约束 |
| --- | --- |
| 独立工作台 | 必需，用户已明确要求；不能作为精简项删除 |
| 三种音频调用类型 | 必需，参数和响应确有差异；只做明确分支，不做插件框架 |
| 提交去重、后台执行 | 必需，防止重复生成并支持离开页面；复用任务表和执行锁 |
| 多版本逐项保存与手动恢复 | 必需，Suno 实际可能多结果；不引入恢复队列和自动重试策略 |
| 表单快照、标题及素材音频类型 | 必需，支持既定改名、再次创作和收藏；不新增独立作品库 |
| 画布节点内版本切换 | 已移出首版，使用单结果节点和任务详情 |
| 每模型独立草稿、通用配置 DSL | 不采用，两个业务表单与现有设置即可 |
| Base64/both、SSE、转码与波形 | 不采用，首版 URL 保存与原文件播放即可完成需求 |
| 新限额、定时清理、通用任务重构 | 不采用，沿用现有机制，必要调整另行确认 |

不因压缩代码而删除鉴权、完整结果保存、去重或失败状态；也不为潜在模型、未知返回格式和未来协作需求提前添加框架。
