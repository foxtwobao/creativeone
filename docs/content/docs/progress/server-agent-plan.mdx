## 目标与状态

建设 **轻量框架 + 现有 Express 后端 + PostgreSQL** 的服务端创作 Agent。首版以画布对话、多步工具调用、内置 Skill 和经授权的媒体生成构成完整流程，不以两个单次生成按钮代替 Agent。用户无需安装本地服务，关闭网页后已受理的运行仍可继续；等待用户补充或确认时保存状态，重新打开可继续。

已对比 AI SDK 配合现有任务机制与 Mastra PostgreSQL 工作流的模拟多步流程，当前选择锁定版本的 AI SDK 单步决策，由现有 PostgreSQL 机制统一保存运行和事务回执。代码在现有服务进程内运行，不新增 Redis、独立 Agent 平台、按用户分配的进程或容器；具体对照和验证边界见「实施记录」。框架负责模型协议与工具解析，项目负责身份、调度、恢复、业务工具和数据一致性。

已实现对话、Skill、画布工具、媒体确认、后台等待及恢复代码，尚未通过真实模型与浏览器完整验收。按用户要求已在 lab 开放候选模型试用，默认发布入口仍关闭；旧本地 `canvasAgent` 与插件入口继续关闭。服务端未配置 `SERVER_AGENT_CONFIG` 时不启动 Agent 执行器。模拟验证使用独立测试库；lab 复用现有 Vite 并重启本项目 API，本轮未主动发起计费模型调用。

## 首版能力与用户流程

首版必须能完成：**读取剧本 → 拆镜 → 创建节点和连线 → 准备图片/视频提示词及素材 → 经授权提交生成 → 后台等待 → 读取结果并反馈**。用户只要求其中一步时，只执行对应范围，不强制走完全部流程。

| 能力 | 首版要求 |
| --- | --- |
| 画布对话 | 理解用户目标，缺少必要条件时提问；支持已有会话继续、停止和重新打开 |
| Skill 调用 | 根据意图和当前阶段加载剧本、分镜、图片、视频规则，可在同一运行内切换组合 |
| 上下文读取 | 读取选中节点、直接上游及按需查询的画布内容；选中项由请求固定，不随浏览器后来切换选区而改变 |
| 多步执行 | 模型调用工具、读取真实结果、决定下一步；保存步骤和运行状态 |
| 画布操作 | 创建普通文本、配置及媒体节点，建立来源连线；使用现有命令、参数和主题 |
| 媒体生成 | 在当前已配置且验证可用的模型范围内，提交现有图片、视频、音频任务，并读取真实结果 |
| 授权与恢复 | 必要时等待确认；支持后台等待、跨用户并发、刷新恢复及未知结果处理 |

示例：用户选择剧本节点，要求“做成一段短片，先拆镜并准备视频”。Agent 读取已保存剧本和模型能力，询问缺失的目标时长，加载拆镜规则，创建镜头文本及视频配置节点。未获得媒体生成授权时，到准备完成为止；用户明确授权具体生成范围后，由 Agent 提交任务并后台等待，完成后报告成功、失败或待处理项目，而不是要求用户逐个手动点击生成。

「拆分镜」「写视频提示词」可以作为助手的预设入口，填入任务意图并携带当前选区，进入同一个会话、Skill 和工具执行链路，不另建单次调用任务体系。点击预设入口不等于授权生成媒体。预设按钮可以最后补齐，不是核心 Agent 的前置条件。

### 精简范围

首版不做导演台、全景图专用节点、自动剪辑成片、Skill 商店、任意脚本或终端、联网搜索、多 Agent、独立草案编辑器、局部候选合并、版本树、专门的差异对照及独立创作记录中心。节点编辑、分组和撤销复用现有画布命令；按用户后续要求增加 Agent 改名、分组、删除及布局，具体范围见「前后台能力对齐」。不新增专用批量撤销。

这些取舍精简产品和基础设施，不移除对话、意图选 Skill、工具循环和媒体编排等 Agent 核心能力。

## 框架验证与选型

| 候选 | 验证重点 |
| --- | --- |
| AI SDK + 现有任务机制 | 模型适配、工具协议及需要补齐的持久调度范围；不把模型 SDK 当作完整持久 harness |
| Mastra 持久工作流 | PostgreSQL 接入、等待/恢复、部署依赖及业务事务衔接是否实际减少自研代码 |

使用同一个最小流程比较：读取测试节点 → 模型选择并调用工具 → 保存决定 → 等待确认 → 进程重启 → 确认后创建节点 → 提交模拟媒体任务 → 后台完成并恢复执行。这个验证直接使用现有领域操作，不要求先制作分镜管理产品。

阶段 A 输出候选对照、实测中断结果、依赖版本、额外部署要求及仍需自行维护的代码清单。优先选满足恢复契约且总体接入成本低的方案，不只比较安装包大小。每个运行只保留一个执行状态权威源，不同时维护框架状态机和一套自研循环。

AI SDK 路线需验证：由 SDK 完成模型请求、工具调用解析及结构化输出；应用先持久化完整模型决定，再执行有副作用的工具并保存结果。不把业务写入放进没有持久检查点的自动循环，也不手写模型协议、流式解析或 JSON 修复框架。是否直接使用 `ToolLoopAgent` 取决于其落库顺序能否满足契约。

持久工作流路线使用框架检查点和暂停恢复；业务写入仍经项目工具。框架检查点与业务事务无法原子提交时，通过事务内工具回执衔接，重放工具返回原结果，不重做副作用；框架不得自动重放结果未知的付费模型请求。

优先验证现有 Responses 路径，覆盖原生工具调用、工具结果续传、结构化输出、拒绝/截断、错误透传及 usage。Chat 只在明确配置且验证通过时选择，不在失败后自动切换协议重发。不完整或不符合 schema 的调用不可执行。模型不支持工具调用时提示不可用于 Agent，不能以普通文本输出冒充完整能力。锁定经验证的稳定依赖，不随官网 latest 自动升级。

## Skill 来源与路由

参考 `tigerowo/infinite-canvas` 的内置创作规则，适配为服务端维护的版本化文本。此处为拟采用内容，不代表已经复制或接入；正式移植前核对许可、署名和来源版本。规则不能携带浏览器执行代码，也不能绕过业务工具权限。

| 规则组 | 参考内容 | 职责 |
| --- | --- | --- |
| 公共执行规则 | `core.ts`、`workflow.ts` | 界定工具能力、阶段推进和真实结果，不虚报完成 |
| 剧本与拆镜 | `script.ts` | 创意/剧本、目标时长、镜头拆解及角色场景需求 |
| 图片与分镜 | `image.ts`、`image-character-sheet.ts`、`image-storyboard.ts` | 角色/场景参考、关键帧、单图及分镜拼图提示词 |
| 视频 | `video.ts`、`video-single-shot.ts`、`video-multi-shot.ts`，按支持能力选择续写/编辑规则 | 单镜头、多镜头、动作、运镜、声音与参考职责 |
| 音频 | `audio.ts`，结合本项目已接入的音频模式适配 | 需要配音或音乐时组织现有音频工具输入 |

不承诺规则里提及的所有媒体能力都可执行，实际以后台配置和共享能力校验为准；缺少能力时明确说明或询问，不假装完成剪辑、混音或视频编辑。

每次模型决策提供公共规则、内置及当前账号个人 Skill 的简短目录及已有激活组。Agent 按意图调用只读 `load_skill` 加载所需内容，再做相应创作；预设入口可直接预选规则组。服务端只允许内置或当前账号已保存的文本 Skill，记录加载内容、附属文件及版本快照，后续恢复使用原快照。用户目标优先于默认创作流程；不用另一个模型做意图分类，不预先塞入全部长规则，不建设可执行 Skill 插件系统。

## 上下文、结果与画布

- 提交前等待当前画布保存成功，服务端校验账号和项目归属，读取选中节点及其直接上游。保存输入、来源版本和模型配置快照；用户后来改变选区不改变本次输入。
- 初始上下文只放必要摘要和相关正文，其他节点按 ID、类型或关键词查询后读取。图片仅在本步骤需要且模型支持时，经服务端展开账号文件；不批量读取整张画布原媒体。
- 多步运行每次操作前读取所需对象的当前状态。输入变化或写入冲突时保存已有结果并提示处理，不静默覆盖新内容或重新发起计费调用。后续用户重新要求修改时，以当前已保存正文为准，历史结果不充当现有节点内容。
- 分镜结构化数据只保存在运行结果中，用于校验和展示；写画布时格式化成普通文本。模型、时长、画幅、分辨率、素材模式写入现有配置字段，参考媒体使用真实文件/节点 ID 和现有连线，不以“参考角色图”文字代替素材绑定。
- 不新增分镜 metadata；正文是后续创作的输入。文本编辑、主版本切换、复制与归档沿用已有行为；运行、确认和工具回执仅存服务端，复制节点不会继承执行身份。
- 修改助手创建且尚未提交生成的节点时，先读取现状并通过 `nodeId` 原位修改，媒体配置与输出成对处理；相同内容、参数和来源复用已有节点。原始剧本、用户自建节点、已提交任务和已有作品保留，正文不提供任意覆盖；删除节点须逐批展示实际对象并经用户确认，已有作品文件与后台任务仍保留。额外副本或新版本须对应用户明确要求。结构化结果未通过校验、素材不足或参数不合法时不得提交媒体任务。

## 工具与授权

| 工具 | 行为与边界 |
| --- | --- |
| `load_skill` | 加载已登记规则组，记录版本，不能注册或执行外部代码 |
| `read_canvas` / `find_nodes` / `read_nodes` | 查询当前项目摘要、选中/上游及按需节点；所有 ID 校验归属 |
| `get_model_capabilities` | 返回公开模型能力与价格摘要，不返回 Key、渠道、分组或插件身份 |
| `create_text_nodes` | 保存用户要求的正文、分镜；相同内容复用，已读取的助手普通文本可按 `nodeId` 修改，过程说明不额外落节点 |
| `prepare_media_nodes` | 准备或复用图片/视频/音频配置与输出，已读取的助手未提交配对可按 `nodeId` 修改，设置现有参数和素材引用，不提交生成 |
| `connect_nodes` | 建立真实直接生产依赖，复用图关系校验；同批创建可直接带来源连线 |
| `submit_generation` | 经服务端授权检查提交现有媒体任务，返回已受理 task ID，不等待网络请求直到媒体完成 |
| `read_task_results` | 读取所属任务已物化结果，不重新请求上游生成 |
| `wait_for_tasks` | 保存需要等待的任务集合后暂停运行，后台就绪唤醒，不让模型循环轮询 |
| `request_user_input` | 保存必要问题或确认内容并暂停，用户回复后在原运行中继续 |

对节点创建、连线等可逆操作，用户已明确要求时直接执行，不机械地每个节点都确认。目标仅为讨论或分析时不擅自写画布。写入前仍校验当前版本；执行回执展示实际创建对象，不能由模型自报成功。

媒体生成授权绑定可审阅的节点、模型、参数、数量和素材。未获得明确授权时，Agent 准备节点并展示生成确认；已有覆盖相同范围的授权可批量执行，无需逐项再问。范围扩大、模型/素材/收费参数改变、再次生成或旧授权不再适用时重新确认。文本推理本身也可能计费，提交入口说明；媒体确认展示可用公开价格，不虚构准确总价。

首版不依赖全局自动生成开关，不授予无限制生成权限。确认由服务端记录并校验，模型不能传“用户已同意”来授权。本次数量与用量边界已经用户确认，见「已确认运行边界」。

## 复用与数据

| 位置 | 实施范围 |
| --- | --- |
| `server/src/tokenone.ts` | 每次模型请求按已验证账号身份取得 Key，沿用授权和模型配置 |
| `server/src/business.ts` | 提取必要画布命令处理供 HTTP 与 Agent 共用，接受同一事务连接 |
| `server/src/ai.ts` | 提取媒体受理函数，保留参数、素材、模型及归属校验 |
| `generation-executor.ts`、`video-tasks.ts`、`canvas-tasks.ts` | 沿用任务领取、媒体查询、保存和结果挂载，不另造媒体执行器 |
| `web/src/services/api/`、画布 store/hook | 新增对话接口及内存展示，复用已有节点、任务详情与作品页面 |

只提取实际需要的函数，不整体重构路由，也不伪造浏览器请求或站内 HTTP 自调用。Agent 推理运行与媒体任务分别保存，并通过 task ID 关联；不重复包装已有媒体任务为另一份生成任务。

建议逻辑数据如下，具体表名及框架存储分工由阶段 A 确定，避免重复维护检查点：

| 数据 | 内容 |
| --- | --- |
| 会话 | owner、project、活动 run ID、会话摘要及时间 |
| 运行 | thread、turn、幂等提交标识、输入与来源版本、模型配置、Skill 快照、状态、执行标识、等待事项和媒体关联 |
| 消息/步骤/回执 | threadId、turnId、itemId；模型决定、tool-call ID、工具参数/结果、usage、唯一操作键及正式实体 ID 映射 |

协议版本与存储格式版本独立管理。新服务端会话不隐式迁移旧本地 Agent 历史；将来确需迁移时遵循先备份、校验并拒绝覆盖异常数据的项目规则。

状态包括 queued、running、waiting_input、waiting_confirmation、waiting_tasks、completed、failed、cancelled、unknown。工具和服务端决定状态，模型不能自由声明任务完成。历史快照是权威，实时预览按 threadId/turnId/itemId 合并，不能重复拼接；不保存永久逐 token 日志。

## 执行、并发与恢复

```text
画布对话 / 预设入口
        ↓ 持久受理，返回 run ID
轻量框架运行 → 读取上下文 / 加载 Skill → 模型决定落库
        ↓
工具校验 → 领域操作与事务回执 → 后续模型步骤
        ↓
等待用户 / 等待已有媒体任务 / 完成
```

1. 先保存输入、操作意图与执行标识，再调用模型；完整响应落库后才执行其中的工具。网络期间不持有项目或用户行锁。
2. 画布命令、正式实体 ID 映射与工具完成回执必须同一 PostgreSQL 事务提交。相同操作键和输入返回原回执，输入不同则拒绝。现有命令回执只包含版本信息且重发会受后续编辑影响，因此工具恢复不重新调用已成功的命令。
3. 媒体受理使用稳定幂等标识；回执丢失按标识找回原 task ID，不创建新生成。确认消费与业务受理建立原子校验或同键查回关系，不能因为框架重放而重复收费请求。
4. 领取通过框架或现有 PostgreSQL 机制保证跨实例互斥，执行标识防止失去归属的旧执行器继续写入。等待用户或媒体时保存状态并释放执行连接和容量，不保持长请求。

不同用户和会话可并发；同会话首版只保留一个活动 run，不做会话内独立请求队列。受理在 thread 行锁内先查幂等提交，再原子设置活动 run；重复提交返回原运行，新独立请求在繁忙时提示继续当前运行、停止或新建会话。输入/确认只在对应等待点接收，不偷偷改写在途输入。

等待时保留活动归属，完成、失败、取消时原子清除归属并失效执行标识。跨会话写同一画布沿用版本校验；同一步多个写工具顺序执行，部分成功如实记录。全局容量不足的已受理运行可以排队，但不是同会话接受多个请求。本次按已确认的全局 2 个执行槽、每账号 1 个和最多 2 条长期执行连接实现；等待释放连接，不以无限 Promise.all 作为实现。

| 中断情况 | 处理 |
| --- | --- |
| 请求尚未发出 | 从持久状态领取执行 |
| 模型已请求而响应未保存 | unknown；可能已计费，不能自动重发；可查回原响应才恢复，否则提示用户决定新尝试 |
| 响应已保存但工具未执行 | 从原响应继续，不再次请求同一步模型 |
| 画布事务提交前中断 | 全部回滚，恢复使用原操作键 |
| 画布事务已提交但检查点丢失 | 读取工具回执，不重建节点；后来删除的节点不会复活 |
| 媒体已受理但 task ID 回执丢失 | 按稳定提交标识查回原任务 |
| 用户编辑来源或删除目标 | 重新检查实际内容，冲突待处理；生成作品按现有任务规则保留 |
| 用户停止 Agent | 阻止后续步骤，尽力停止网络等待；已受理媒体不宣称取消或退款，迟到结果不恢复 Agent |

数据库锁不保证上游恰好计费一次。所有副作用入口都校验执行归属，框架自动重试不能绕过未知结果策略。

### 媒体等待

| 子任务情况 | 父运行行为 |
| --- | --- |
| 全部必要任务成功 | 幂等唤醒，读取结果并执行用户授权范围内的下一步，最终反馈结果 |
| 必要任务仍运行 | waiting_tasks；后台观察，关闭网页不影响 |
| 失败、取消或部分失败 | waiting_input，展示成功/失败/仍运行项；可用成功项继续或结束，不自动补生成 |
| unknown | waiting_input，提供查询/恢复原任务、使用已有成功项继续或结束；没有可用结果时不提供成功项继续 |

等待集合及用户选择保存版本，通过条件更新和唯一续执行步骤去重。后台扫描补回遗漏通知，不能只依靠网页或临时事件。恢复仅查询或保存原任务，不重新生成。明确排除的任务迟到后只保留原作品；已结束父运行不复活。需要新生成时重新明确授权并提示重复计费风险。

## 前端和接口

新增一个画布助手面板，复用当前画布视觉风格，展示对话、真实工具动作、当前等待事项、必要确认、停止入口及关联节点/任务。支持会话列表和权威历史找回，这是 Agent 必要界面；不新增草案中心或重复的作品管理页。图片、视频、音频结果继续进入已有生成任务和作品入口。

## 身份与边界

Key 仅服务端按已绑定用户身份获取，不写入运行记录、日志或浏览器 DTO；长任务不依赖原 Cookie 持续在线，但每次调用仍经现有授权机制，撤销或失效时暂停后续调用。模型不能指定任意账号、上游 URL 或 Key。

剧本、素材、节点正文是输入数据，不授予权限。工具经 schema 与领域规则校验，文件按账号检查归属，普通用户界面不显示内部供应商信息。上下文只读取必要内容。按用户要求对齐参考项目的自动摘要：完整历史保留，模型输入在估算达到 260000 token 或上游明确拒绝上下文过长时尝试压缩，近期完整轮次与当前固定输入继续保留；无法有效压缩时暂停并提示处理，不静默删除或裁剪历史。

### 已确认运行边界

以下默认值已由用户确认；运行保存当次预算快照。单次输出原为 8000 token，用户后续选择按上游模型限制执行，现已取消应用层默认上限；这不等于自动获取或拉满模型最大输出量。上下文压缩按用户后续“对齐参考项目”指示采用 260000 / 64000 / 16000 token 估算预算，替换原 120000 字符检查；摘要使用当前推理模型并计入每段 24 次调用。累计 80000 token 暂停已按后续确认取消，用量继续记录，旧配置快照中的阈值不再参与运行判断。上游明确拒绝上下文过长后允许压缩并继续一次，仍失败就暂停，未知结果不重发。以后调整这些边界仍须按项目规则另行确认，不叠加 SDK 默认重试，也不修改已有媒体任务限制。

| 边界 | 已确认默认值 | 达到后处理 |
| --- | --- | --- |
| 全局 / 账号并发 | 全局 2、每账号 1；最多 2 条长期执行连接 | 已受理运行排队；扫描和短事务沿用现有共享数据库池 |
| 模型调用次数与用量 | 每段 24 次模型调用（含摘要）；累计 token 仅统计 | 达到次数后保存成果并等待明确继续，不发下一次请求；累计 token 不触发暂停，不提供精确费用封顶 |
| 模型请求 | 600000 ms；SDK 和业务自动重试均为 0 | 已发出而响应未保存记 unknown；不自动切换协议 |
| 上下文 / 输出 | 估算输入 260000 token 触发压缩，近期约 64000 token，摘要正文至多约 16000 token；单次输出采用上游默认 | 旧 120000 字符检查移除；超长当前输入没有可压缩旧轮次时交由上游判断，明确拒绝后仍无法缩减则暂停。输出截断不执行工具或自动重试 |

| 后台 / 前端状态查询 | 后台沿用 5000 ms；前端活动状态 3000 ms | 前端隐藏暂停，等待用户时不轮询；后台等待不依赖网页 |
| 历史保留 | 不自动删除，不按大小裁剪 | 未知存储版本拒绝读取与覆盖 |

只在已确认边界下开放对应执行能力，不借本方案修改既有媒体任务超时和限制。

### 自动压缩的实施与恢复

- 默认按文本与工具 schema 估算模型输入，并以上游真实 input usage 校正估算比例；达到 260000 token 时尝试压缩。这个数是触发值，不是声明所有模型都支持的窗口大小；较小窗口仍可能由上游明确拒绝。
- 保留当前用户目标及固定选区输入，近期完整轮次按约 64000 token 预算保留；工具调用和回执成对保留，未完成轮次不进入摘要。摘要正文至多约 16000 token，有真实正文用量时一并校验，过长或不完整时拒绝使用，不截取摘要尾部。
- `agent_runs.context`、原消息、模型响应和工具回执不改写、不删除。派生检查点仅保存摘要、历史切换位置与恢复标记；发给模型的是摘要、当前固定输入和近期完整轮次。新运行沿用同一会话的检查点，继续追加完整原始历史。
- 摘要使用该运行已登记的推理模型，每次重新检查当前授权，不带业务工具；用量继续累计，摘要请求次数计入每段 24 次模型调用。达到调用次数边界时仍须用户明确继续，累计 token 不触发暂停。摘要不授予媒体生成权限，实际节点、任务和授权继续由现有领域工具检查。
- 明确的输入上下文超限才触发压缩后继续一次；其他拒绝、限流、超时或未知响应不触发这条路径。压缩后仍被上游拒绝则暂停；没有可压缩旧轮次时保留原输入并提示缩小。摘要请求失败或摘要不可用时显示手动重试入口，未知摘要结果不能自动重发。
- 摘要请求先写入 requesting 检查点，完整响应保存后再应用；摘要和切换位置、步骤收尾在同一事务提交。响应保存后重启可直接应用原摘要，检查点提交后不重复摘要；失去执行归属或用户停止后，迟到摘要不能覆盖现有检查点。

### 工具参数错误与原运行继续

lab 后续一次视频准备失败的完整响应为 `completed`，并非输出截断：视频画幅使用了 `ratio` / `size`，而当前画布字段为 `videoSize`；之前的 `2.5` 秒尝试违反现有视频整数时长规则。此前只返回笼统的能力错误，导致模型反复创建试探请求。

- 媒体准备 schema 按图片、视频、音频区分参数，视频明确使用 `videoSize`、`vquality` 与整数秒字符串 `seconds`。能力工具返回对应字段和现有型号范围；没有新增时长上限、自动舍入或字段别名，图片继续使用 `size`。
- 完整但参数不符合 schema 的决定整体不执行，保留原始响应并展示具体字段问题，等待用户明确点击「修正参数并继续」。继续时把该决定的调用与错误回执成对补入上下文，要求模型仅修正未完成部分，不重复成功节点、不创建试探节点；原总时长与整数秒冲突时先询问用户，不擅自调整。
- 手动继续保持同一运行和原预算，不自动请求模型，不授予媒体生成权限；账号、线程占用和等待版本均须匹配。截断、拒绝、重复调用 ID 或结果未知不进入该恢复路径。
- 业务能力校验向模型返回具体原因，保留现有事务与回执机制。界面工具结果显示节点类型，区分同名配置与媒体输出节点。

### 节点复用与未提交节点修改

真实回执显示，用户要求把六镜改为 9:16 时，原工具只有创建能力且规则默认派生新版本，因此新增了一整组配置与视频；过程方案也反复写成文本。现调整为优先复用与修改未提交节点：

- 文本和媒体准备接受可选 `nodeId`。修改仅作用于当前项目中助手已创建、已读取的节点；媒体配置与唯一输出成对读取和更新，保留实体 ID、位置及配对关系，按本次明确输入调整来源连线并刷新来源校验。
- 相同正文按内容与来源复用；媒体使用共享 `canvasRequestBody` 转换后的实际请求比较，音频进一步使用共享 `audioRequestBody` 排除非调用字段，并保留模型、来源和参考文件匹配。省略默认值、显式默认值、等价尺寸或未实际生效的音频字段不导致新副本；真实调用参数有变化时不误合并。这条规则跨工具调用、运行和会话生效，不按相似标题或语义猜测合并内容。同名同来源但内容有变化时返回已有 ID，要求读取并明确修改目标，避免默认新增副本。用户明确要求额外副本或多个版本时可使用 `newCopy`，不能与原位修改混用。
- 原始剧本、用户自建节点、已提交任务与已有作品不能原位覆盖；即使生成标记被移除，也按实际任务记录拒绝。修改和工具回执在原事务中提交，整批失败回滚；已保存回执继续由原检查点恢复机制读取，不重复创建。
- 节点参数或素材修改使原生成确认失效，新生成仍须审阅具体范围。此能力不提交媒体任务、不删除旧节点，不改变预算、批量或重试边界。
- 每次决策提供当前工具规则，已有对话与规则快照不改写。方案说明、参数清单、进度与总结按规则留在对话，用户明确要求时才另存节点；该创作意图仍需模型遵守，不将不同正文强行视作重复。回执与界面明确新建、更新、复用。
