# WAN3 统一协议接入方案

状态：已在 `codex/wan3-unified-api` 分支完成 CreativeOne 接入与模拟上游回归。29 项前端测试、6 项共享请求与能力测试、48 项隔离 PostgreSQL 接口测试通过；未执行构建或语法检查。当前应用配置的 lab 公开价格目录及 `AGENTONE-Creative` 目录均未包含两个新公共模型，真实路由、定价与供应商生成待联调。

依据：New API 仓库根目录 `WAN3_CHANNEL_INTEGRATION_PLAN.md`，本机路径 `/home/hulei/projects/newapi/WAN3_CHANNEL_INTEGRATION_PLAN.md`。该文档包含早期目标与后续实施记录；存在差异时以最新实施记录和目标实例实查为准，不能把规划能力视为已经上线。

## 1. 目标与范围

将 CreativeOne 的 WAN 调用从 RollDek 旧协议切换为 New API 公共协议。工作台、画布和其他复用同一请求构造函数的入口采用同一套模型、参数与结果下载流程，由 New API 选择供应商。

- 新生成使用 `wan3.0-video`、`wan3.0-video-prime`；两种模型分别配置为 WAN 类型，不按名称合并或推导展示描述。
- 画质使用独立参数，支持 `480P`、`720P`、`1080P`。
- 继续由登录后的服务端获取应用 Key，保存任务、后台查询并把结果保存到文件卷。
- 只修改 CreativeOne；不修改、构建或部署 New API、Reseller，不在客户端复制插件路由或计费逻辑。
- 本期不增加供应商选择、高级音频/seed 参数、自动时长、自动主备或旧请求格式兼容层。

## 2. 接入前差异

| 环节 | 当前实现 | 目标 |
| --- | --- | --- |
| 模型能力 | `shared/video-models.ts` 只登记带画质后缀的 WAN 模型，`wanModelProfile` 要求固定分辨率 | 登记两个公共模型及可选画质，移除新提交对后缀的依赖 |
| 请求构造 | `shared/video-request.ts` 使用 `seconds`、`aspect_ratio`、`reference_*` | 显式 `duration`、`resolution`、`ratio`，素材统一放入 `metadata.input.media` |
| 服务端校验 | `server/src/ai.ts` 的严格 schema 仅接受旧字段 | 校验公共结构，拒绝重复素材入口和未支持的生成字段 |
| 参数边界 | WAN 时长只要求正整数；首尾帧与视频、音频混用未拦截 | 固定时长边界按确认后的方案实施，补齐公共素材组合约束 |
| 结果保存 | `server/src/video-tasks.ts` 强依赖 `metadata.url` | 从公共 `/content` 接口取得视频字节 |
| 历史恢复 | `server/src/task-history.ts` 和 `shared/generation-request.ts` 读取旧素材字段 | 从公共请求快照恢复角色、素材和生成设置 |

JSON 提交、创建与查询接口路径、后台任务处理方式可以沿用。旧入口的成功记录只证明旧流程可用。

## 3. 请求契约

创建：`POST /v1/videos`，`Content-Type: application/json`。以下为完成服务端素材签名后发送到 New API 的请求示例；URL 为占位符。

```json
{
  "model": "wan3.0-video",
  "prompt": "人物缓缓转头，镜头保持稳定",
  "duration": 6,
  "resolution": "720P",
  "ratio": "16:9",
  "metadata": {
    "input": {
      "media": [
        { "type": "first_frame", "url": "https://example.com/start.jpg" }
      ]
    }
  }
}
```

文生视频省略素材 metadata；普通参考素材类型为 `reference_image`、`reference_video`、`reference_audio`，帧模式使用 `first_frame` 和可选 `last_frame`。同一请求只使用一个素材入口，不发送 `reference_*`、顶层 media 或 `input.media`。

内部设置继续使用现有 `480` / `720` / `1080` 和 `auto` 表示；唯一的共享构造函数负责转为大写画质与 `adaptive`。服务端画布权威请求也调用此函数，不能只修改浏览器请求。

素材角色与顺序必须保留，不去重、不重写提示词中的“图1”等引用，也不擅自转换为 `@1`。现有界面分别管理图片、视频和音频，发送顺序应固定且在工作台、画布与历史中一致，不宣称能够还原未保存的跨类型拖拽顺序。

本期不发送 `metadata.parameters`：当前 WAN 界面未开放高级参数，尤其不能把通用设置中的默认 `false` 自动写成 `audio: false`，导致可用渠道减少。

## 4. 参数与素材边界

用户要求开分支按方案修改后，本次采用以下边界；未新增表格以外的调用上限。

| 项目 | 提案 | 校验失败处理 |
| --- | --- | --- |
| 固定输出时长 | 2–30 秒整数；未设置时保留 CreativeOne 默认 6 秒；首期不开放自动时长 | 前端提示、服务端拒绝，不调用 New API，不截断或自动改值 |
| 画质 | 三档；沿用有效的当前选择，空值使用现有 720P 默认；每次显式发送 | 非法值提示重新选择，不依赖网关默认 1080P |
| 画幅 | `16:9`、`9:16`、`1:1`、`4:3`、`3:4`、自动 | 应用按公共契约校验；自动发送 `adaptive`，由 New API 筛选支持所选画幅的渠道 |
| 首尾帧 | 一张首帧、至多一张尾帧；不与普通参考图、视频、音频混用 | 提交前明确提示，不丢弃素材 |
| 提示词 | 保留当前非空要求 | 不伪造提示词，不在首期扩展百炼纯素材能力 |
| 参考图数量 | 保留现有最多 10 张 | 保留现有超限提示 |
| 视频、音频数量与时长 | 不把知梦规划限制或 RollDek 预扣估算直接设为全局上限 | 已知组合在本地校验，供应商能力由 New API 候选筛选；明确显示脱敏错误 |

固定时长从“正整数”收紧到 2–30 秒，作用于工作台、画布和服务端所有 WAN 新提交；默认 6 秒，越界阻止提交，无自动回退。首尾帧与普通参考素材混用也在提交前拒绝。

沿用既有文件大小限制、签名有效期、后台扫描间隔、查询及下载超时，不新增重试次数、并发或等待上限；若后续确需调整，单独说明默认值与失败处理并取得确认。

## 5. 素材、快照与历史

1. 浏览器提交现有账号文件引用，由服务端检查文件归属、类型和已登记的大小/时长规则。
2. 数据库中的请求快照保存可持久引用的本项目文件地址；仅在发送 New API 前，把 `metadata.input.media[*].url` 替换为现有单文件 HTTPS 签名地址，避免历史依赖过期链接。
3. 同步修改工作台和画布的素材遍历、签名、文件引用提取及清理逻辑；嵌套结构不能绕过权限检查或导致仍被引用的文件被清理。
4. 历史从公共快照恢复画质、时长、画幅、模式和素材角色；不从模型名或当前页面设置补算任务参数。
5. 不编写旧字段迁移或兼容兜底，不批量改写历史任务。已经保存的视频继续使用服务端文件结果；旧快照参数重放不在本期保证范围。

公网可达性是素材联调前提。lab 的内网域名签名链接不能直接供远端供应商下载；统一字段不会解决 DNS 问题。继续跟踪现有素材公网入口 TODO，不临时引入外部存储或放宽访问控制。

## 6. 查询与结果下载

- 查询继续使用 `GET /v1/videos/{task_id}`；按任务已有归属及服务端身份取 Key，保持账号和分组校验，不受当前页面选中模型影响。
- 任务完成后，由服务端请求配置的 TokenONE 地址下的 `GET /v1/videos/{task_id}/content`，携带该任务所属用户的应用 Key。
- 下载目标由服务端固定构造，不能取响应任意 URL 再附加 Authorization。继续拒绝重定向，避免凭据流向其他域名；不实现供应商直链回退。
- 复用 `readBytes`、现有大小限制和 `saveDownloadedMedia`，检查响应状态与媒体类型；JSON 错误页、空响应或下载失败不得保存为成功视频。无需把通用远端下载器改成任意地址携带凭据的接口。
- 浏览器继续读取 CreativeOne 保存后的文件与缩略图；后台完整保存使用 GET，无需先发 HEAD。公共 HEAD/Range 可作为网关联调项，本项目媒体播放沿用已有文件服务。
- 查询临时失败沿用后台续查；下载/保存失败沿用现有暂停及手动续查同一任务流程。任何阶段不得通过重新 POST 来“恢复”已创建任务。

已有任务 ID 仍可沿原查询流程处理；切换前应核实旧任务的公共内容下载是否可用。若有尚未完成的旧任务，优先完成或暂停切换，不为本次方案额外增加旧直链下载分支。

## 7. 上游实际能力与联调条件

New API 文档的实施记录明确：

- 最新实施记录中的知梦 1.1.2 已支持固定时长文生视频、首帧、首尾帧、普通参考图及音频；参考视频仍因缺少可信输入及输出计费用量而拒绝。这是上游代码能力记录，仍需核实目标实例插件版本和真实供应商表现，不能承诺三家均可处理所有素材。
- 公共模型不能被静态映射到 RollDek 某个画质后缀；供应商模型转换由插件根据画质执行。
- 宿主的提交不确定结果保护已撤回，有重试预算时仍存在重复生成风险。CreativeOne 不自动重提不能代表 New API 也不重试；真实联调前需在对应项目确认运行配置和行为，不在本任务修改网关重试设置。
- 上游缺失或非法完成用量仍可能保留预扣。CreativeOne 不自行估算账单；成功保存不等于供应商账单已核对。

联调前只读确认：目标实例确有两个公共模型、应用分组能路由到它们、按画质配置定价、模型列表可见、素材链接对供应商可达。用户说明已升级是实施前提，但不能替代这些检查。

## 8. 实施顺序

1. 采用第 4 节边界完成客户端接入，真实联调前核实目标 New API 实例能力。
2. 调整共享 WAN 能力表和请求构造，移除新提交的后缀模型分支；后台只允许配置两个新公共模型为 WAN 类型。
3. 同步服务端严格校验、普通请求与画布权威请求的素材签名、权限及文件引用处理。
4. 更新 WAN 结果下载为公共内容接口，保留现有任务锁、状态持久化、失败恢复和文件保存机制。
5. 同步参数面板与历史解析；核对 Agent 工具等复用入口，不新增简单转发组件或另一套请求转换器。
6. 执行必要的定向验证，再由管理员显式调整启用模型。不要把旧型号或 `wan3.0-image-*` 自动映射成新型号，不直接改数据库中的用户配置。
7. 实际改动完成后记录 CHANGELOG 的 Unreleased，并把已实现事项从 TODO 移到待测；真实验收通过后再更新功能说明。

预计主要涉及 `shared/video-models.ts`、`shared/video-request.ts`、`shared/canvas-request.ts`、`shared/generation-request.ts`、`web/src/lib/video-settings.ts`、`web/src/services/api/video.ts`、`server/src/tokenone.ts`、`server/src/model-capabilities.ts`、`server/src/ai.ts`、`server/src/video-tasks.ts`、`server/src/task-history.ts` 及实际引用这些字段的文件管理代码。按需要修改已有设置组件和测试，不扩展到 Seedance 或其他模型重构。预计不需要数据库 schema 变更。

## 9. 验收标准

| 验收项 | 通过标准 |
| --- | --- |
| 请求一致性 | 工作台、画布发往上游的模型、时长、画质、画幅和素材结构一致；无旧字段、隐式高级参数 |
| 参数边界 | 覆盖 2、30 秒有效及 1、31 秒无效；非法枚举、单独尾帧及混合帧模式在提交前失败 |
| 素材归属 | 嵌套引用仍执行账号检查和签名；角色、顺序不变；快照不保存临时签名链接 |
| 下载保存 | 完成响应没有 `metadata.url` 仍可保存；Authorization 仅发往配置网关；拒绝重定向与非媒体错误响应 |
| 后台恢复 | 关闭页面后继续处理；查询故障不重提；下载失败恢复沿用原 ID；并发处理不重复保存 |
| 历史与配置 | 公共模型可配置；新请求的画质、时长和素材正确回显；界面不再要求分辨率后缀 |
| 回归 | Seedance 请求与下载、已有文件播放、账号隔离不受影响 |
| 真实联调 | 先文生视频，再在素材可达且渠道支持时验证帧和参考任务；核对真实渠道、公共模型、画质与账单 |

优先补充已有请求、模型能力和后端集成测试，使用模拟上游验证请求次数、鉴权目标与故障恢复。遵循项目约定，不执行语法检查或构建。真实收费生成需获得明确授权后执行；离线测试不能替代素材语义、实际渠道及账单验收。

本轮已完成上述代码改动，测试覆盖公共请求序列化与画布一致性、参数边界、嵌套素材归属与类型、持久快照和历史、公共内容下载、非媒体/重定向/空响应失败、同任务恢复及 Seedance 回归。集成测试使用真实隔离 PostgreSQL 数据库与模拟上游，临时测试数据库和媒体目录已清理；修正了非成功二进制下载响应被错误解析为文本的问题。未进行真实供应商生成、构建或语法检查，未修改启用模型、上游配置或关联项目。实施记录见待测清单。
