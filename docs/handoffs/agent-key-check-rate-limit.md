## 关联项目建议

1. 在 New API 项目核对只读凭据查询是否应继承关键操作的共享 IP 桶。为受身份保护的只读接口采用明确的独立作用域和预算，避免多个账号或应用因同一代理来源相互占用；具体次数、窗口和失败处理须在对应项目说明并确认，不能直接取消保护或改成无限制。
2. 在 Reseller 项目明确上游 429 的稳定错误合同，并保留可用的等待信息（例如 Retry-After）；与授权失效、普通服务故障分别处理。不要把所有凭据检查错误都转换为同一种 503，也不要自动重放计费请求。
3. 合同确认后再更新 CreativeOne 的安全错误映射与提示。当前应用只收到通用 503，不能将所有此类错误都臆测为限流；继续逐次检查授权，不在浏览器保存 Key，不用长时间缓存绕过上游权限撤销。

## 用户继续方式

限流窗口恢复后，在原会话点击「检查服务并继续」。检查成功才会请求下一步推理，实际媒体生成继续遵循批次确认。若再次暂停，按新的服务记录排查，不反复重新授权或重建任务。
